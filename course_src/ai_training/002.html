Introduction

Every step of neural network training boils down to an orchestration of four sequential phases: evaluating a candidate prediction through a forward pass, measuring prediction discrepancy via a loss function, calculating exact parameter gradients by reversing the computation through backpropagation, and adjusting weights using an optimization rule [1]. While inference executes only the forward pass and discards intermediate results as soon as each layer finishes, training is bound by the mathematical demands of the backward pass. Backpropagation requires access to the intermediate activations generated during the forward pass to compute parameter gradients, forcing the system to store gigabytes of transient state across every layer of the model [2].

Furthermore, training exhibits a fundamental computational asymmetry: the backward pass costs roughly twice the floating-point operations (FLOPs) of the forward pass. For a standard linear projection, the forward pass performs a single matrix multiplication to project input activations into output representations. The backward pass, however, must perform two distinct matrix multiplications: one to backpropagate the error gradient to preceding layers, and a second to compute the gradient with respect to the layer weights [3]. This reality establishes the canonical 6ND rule of language model pretraining—each token requires approximately 6N FLOPs per step (2ND forward and 4ND backward for N parameters and D tokens), rising to 8ND when activations are recomputed to save GPU memory [4].

The training loop cycle: forward evaluation transforms inputs and weights into activations (2ND FLOPs), loss evaluation computes scalar error against vocabulary targets, backward backpropagation evaluates input and weight gradients (4ND FLOPs), and the optimizer updates master weights before clearing temporary gradients.

In this lesson, we examine the mathematical foundations and systems engineering of the forward and backward passes. We walk through a hand-calculated numeric backpropagation example on a two-layer network, analyze how next-token cross-entropy loss behaves across high-dimensional vocabularies, prove why the backward pass requires twice the compute of the forward pass, and dissect PyTorch autograd mechanics and gradient accumulation during large-scale pretraining.

The question underneath is: How do we map the mathematical chain rule onto modern GPU hardware, budget the computational FLOPs and transient memory buffers for an 8B model, and coordinate micro-batch execution to maintain 40% hardware efficiency? To answer it, we begin with the core mechanics of backpropagation.

The Mechanics of Backpropagation

The computation graph

Modern deep learning frameworks represent mathematical expressions as a directed acyclic graph (DAG) known as a computation graph [2]. In this graph, leaf nodes represent input data tensors or learnable model parameters (weights and biases). Internal nodes represent mathematical operations, such as matrix multiplications, bias additions, layer normalizations, or non-linear activation functions. Directed edges represent the flow of multi-dimensional arrays (tensors) between operations.

Forward operations (black solid arrows) construct an acyclic evaluation graph from inputs and weights to scalar loss. During the backward pass (red dashed arrows), gradients flow in reverse topological order, generating weight updates (orange) and propagating error signals back to prior layers.

During the forward pass, the framework traverses the graph in topological order, executing GPU kernels to compute intermediate tensors until it evaluates the scalar loss \mathcal{L}. When an operation executes, PyTorch records an internal backward node (a subclass of torch.autograd.Function) containing the recipe for computing vector-Jacobian products for that operation. During the backward pass, the framework traverses this graph in exact reverse topological order, seeding the root with \frac{\partial \mathcal{L}}{\partial \mathcal{L}} = 1.0 and propagating gradients backward toward the parameters.

The chain rule in reverse

Consider a composite function where an input x undergoes a sequence of transformations z_1 = f(x), z_2 = g(z_1), producing output y = h(z_2) evaluated by scalar loss \mathcal{L}(y). According to the multivariable chain rule of calculus, the sensitivity of the loss with respect to the input is the product of intermediate Jacobians:

\frac{\partial \mathcal{L}}{\partial x} = \frac{\partial \mathcal{L}}{\partial y} \frac{\partial y}{\partial z_2} \frac{\partial z_2}{\partial z_1} \frac{\partial z_1}{\partial x}

In forward-mode automatic differentiation, derivatives are evaluated from left to right (from inputs toward outputs). For a neural network with N parameters and a single scalar loss \mathcal{L}: \mathbb{R}^N \to \mathbb{R}, forward-mode differentiation would require N separate forward sweeps through the graph, scaling proportionally to parameter count. In reverse-mode automatic differentiation (backpropagation), derivatives are evaluated from right to left (from the scalar loss back toward the parameters). Because the output is a single scalar (\mathbb{R}^1), a single reverse sweep computes the exact gradient with respect to all N parameters simultaneously [1].

Worked numeric example: a two-layer network by hand

To demystify backpropagation, let us trace a complete numeric forward and backward pass on a concrete, two-layer bias-free network small enough to verify with paper and pencil. Let the input vector be x \in \mathbb{R}^2, the first weight matrix be W_1 \in \mathbb{R}^{2 \times 2}, the activation function be a rectified linear unit (\text{ReLU}), the second weight vector be W_2 \in \mathbb{R}^{1 \times 2}, and the target scalar be y:

x = \begin{bmatrix} 2.0 \\ 1.0 \end{bmatrix}, \quad W_1 = \begin{bmatrix} 1.0 & 0.5 \\ -0.5 & 2.0 \end{bmatrix}, \quad W_2 = \begin{bmatrix} 0.8 & -1.2 \end{bmatrix}, \quad y = 1.8

1. Forward pass evaluation

First, compute the linear projection of Layer 1:

z_1 = W_1 x = \begin{bmatrix} 1.0(2.0) + 0.5(1.0) \\ -0.5(2.0) + 2.0(1.0) \end{bmatrix} = \begin{bmatrix} 2.0 + 0.5 \\ -1.0 + 2.0 \end{bmatrix} = \begin{bmatrix} 2.5 \\ 1.0 \end{bmatrix}

Next, apply the elementwise ReLU activation function a_1 = \max(0, z_1). Because both components of z_1 are positive:

a_1 = \text{ReLU}\left(\begin{bmatrix} 2.5 \\ 1.0 \end{bmatrix}\right) = \begin{bmatrix} 2.5 \\ 1.0 \end{bmatrix}

Next, compute the linear projection of Layer 2 to produce prediction \hat{y}:

\hat{y} = W_2 a_1 = \begin{bmatrix} 0.8 & -1.2 \end{bmatrix} \begin{bmatrix} 2.5 \\ 1.0 \end{bmatrix} = 0.8(2.5) + (-1.2)(1.0) = 2.0 - 1.2 = 0.8

Finally, evaluate the mean squared error loss \mathcal{L} = \frac{1}{2}(\hat{y} - y)^2:

\mathcal{L} = \frac{1}{2}(0.8 - 1.8)^2 = \frac{1}{2}(-1.0)^2 = 0.50 Step-by-step arithmetic verification: forward evaluation generates intermediate activations z1 = [2.5, 1.0] and scalar prediction 0.8. Reverse backpropagation multiplies error signals by stored activations to calculate exact gradients dL/dW2 and dL/dW1.

2. Backward pass backpropagation

Now we execute the chain rule in reverse, starting from the loss:

Step 1: Output error gradient. Differentiate the loss with respect to prediction \hat{y}:

\delta_y = \frac{\partial \mathcal{L}}{\partial \hat{y}} = \hat{y} - y = 0.8 - 1.8 = -1.0

Step 2: Gradients at Layer 2. Differentiate with respect to weight vector W_2 and hidden activation a_1:

\frac{\partial \mathcal{L}}{\partial W_2} = \delta_y a_1^\top = -1.0 \begin{bmatrix} 2.5 & 1.0 \end{bmatrix} = \begin{bmatrix} -2.5 & -1.0 \end{bmatrix} \frac{\partial \mathcal{L}}{\partial a_1} = W_2^\top \delta_y = \begin{bmatrix} 0.8 \\ -1.2 \end{bmatrix} (-1.0) = \begin{bmatrix} -0.8 \\ 1.2 \end{bmatrix}

Notice the critical systems insight: computing \frac{\partial \mathcal{L}}{\partial W_2} requires the forward activation a_1. If the GPU had freed a_1 after the forward pass, it could not calculate the weight gradient.

Step 3: Gradients through ReLU. The derivative of ReLU is the unit step function \mathbf{1}(z_1 > 0). Multiplying elementwise:

\delta_1 = \frac{\partial \mathcal{L}}{\partial z_1} = \frac{\partial \mathcal{L}}{\partial a_1} \odot \mathbf{1}(z_1 > 0) = \begin{bmatrix} -0.8 \\ 1.2 \end{bmatrix} \odot \begin{bmatrix} 1 \\ 1 \end{bmatrix} = \begin{bmatrix} -0.8 \\ 1.2 \end{bmatrix}

Step 4: Gradients at Layer 1. Differentiate with respect to weight matrix W_1 and input vector x:

\frac{\partial \mathcal{L}}{\partial W_1} = \delta_1 x^\top = \begin{bmatrix} -0.8 \\ 1.2 \end{bmatrix} \begin{bmatrix} 2.0 & 1.0 \end{bmatrix} = \begin{bmatrix} (-0.8)(2.0) & (-0.8)(1.0) \\ (1.2)(2.0) & (1.2)(1.0) \end{bmatrix} = \begin{bmatrix} -1.6 & -0.8 \\ 2.4 & 1.2 \end{bmatrix} \frac{\partial \mathcal{L}}{\partial x} = W_1^\top \delta_1 = \begin{bmatrix} 1.0 & -0.5 \\ 0.5 & 2.0 \end{bmatrix} \begin{bmatrix} -0.8 \\ 1.2 \end{bmatrix} = \begin{bmatrix} 1.0(-0.8) + (-0.5)(1.2) \\ 0.5(-0.8) + 2.0(1.2) \end{bmatrix} = \begin{bmatrix} -0.8 - 0.6 \\ -0.4 + 2.4 \end{bmatrix} = \begin{bmatrix} -1.4 \\ 2.0 \end{bmatrix}

Every number aligns with machine precision. The outer product \delta_1 x^\top demonstrates why computing the parameter gradient \frac{\partial \mathcal{L}}{\partial W_1} strictly depends on retaining the input tensor x in memory.

Next-Token Prediction and Cross-Entropy Loss

The language modeling objective

Modern autoregressive large language models are trained using self-supervised next-token prediction. Given an input sequence of discrete token indices (x_1, x_2, \dots, x_T), the joint probability distribution decomposes via the probability chain rule:

P(x_{1:T}) = \prod_{t=1}^T P(x_t \mid x_{

At each sequence position t, the transformer backbone outputs a normalized continuous representation h_t \in \mathbb{R}^{d_{\text{model}}}. The language model head projects this vector across the entire vocabulary of size V using embedding weight matrix W_{\text{vocab}} \in \mathbb{R}^{V \times d_{\text{model}}} to produce raw unnormalized logits z_t \in \mathbb{R}^V:

z_t = W_{\text{vocab}} h_t

The softmax function converts these logits into a valid categorical probability distribution over the vocabulary:

p_{t, i} = \frac{\exp(z_{t, i})}{\sum_{j=1}^V \exp(z_{t, j})}

Given ground-truth target token index y_t \in \{1, \dots, V\}, the training objective minimizes the cross-entropy loss, which corresponds to the negative log-likelihood of the correct token:

\mathcal{L}_t = -\log p_{t, y_t} = -z_{t, y_t} + \log\left( \sum_{j=1}^V \exp(z_{t, j}) \right) The LM head projects hidden state h across vocabulary size V (128,256), softmax produces probability vector p, and cross-entropy evaluates error against target token y. Backpropagation yields the elegant gradient dL/dz = p - y, shifting probability mass directly toward the target.

The gradient w.r.t. logits: p - y

To backpropagate through the loss, we calculate the partial derivative of \mathcal{L}_t with respect to any arbitrary logit z_{t, i}. Using calculus on the expanded log-sum-exp expression:

\frac{\partial \mathcal{L}_t}{\partial z_{t, i}} = -\frac{\partial z_{t, y_t}}{\partial z_{t, i}} + \frac{1}{\sum_{j=1}^V \exp(z_{t, j})} \frac{\partial}{\partial z_{t, i}} \left( \sum_{j=1}^V \exp(z_{t, j}) \right)

The first term equals -1 if i = y_t and 0 otherwise, written compactly using the indicator function -\mathbf{1}(i = y_t). In the second term, only the j = i term has a non-zero derivative, yielding \exp(z_{t, i}):

\frac{\partial \mathcal{L}_t}{\partial z_{t, i}} = -\mathbf{1}(i = y_t) + \frac{\exp(z_{t, i})}{\sum_{j=1}^V \exp(z_{t, j})} = p_{t, i} - \mathbf{1}(i = y_t)

In vector notation, where y_t is represented as a one-hot vector with 1 at the target index, this gradient simplifies to:

\nabla_{z_t} \mathcal{L}_t = p_t - y_t

This result provides deep intuition: the error signal feeding into the backward pass is simply the difference between the model's predicted probability distribution and the true ground-truth distribution. For every incorrect token (i \neq y_t), the gradient is positive (+p_{t, i}), pushing its logit downward during gradient descent. For the target token (i = y_t), the gradient is negative (p_{t, y_t} - 1 < 0), driving its logit upward.

The memory bottleneck of large vocabularies

While the mathematical form p - y is simple, its physical materialization on GPUs represents a notorious memory bottleneck. In Llama 3.1 8B, the vocabulary size is V = 128,256. For a micro-batch of b = 1 with sequence length s = 8,192, the logits tensor z contains:

1 \times 8,192 \times 128,256 = 1,050,673,152\text{ elements}

Because softmax and cross-entropy require full 32-bit floating-point precision to prevent numerical overflow in the exponent sum, storing this unchunked logit tensor requires 1.05 \times 10^9 \times 4\text{ bytes} \approx 4.20\text{ GB} of memory for a single sequence. Storing the corresponding probability tensor and backward gradient adds another 8.4 GB, consuming over 12 GB of GPU High Bandwidth Memory (HBM) purely for the loss calculation.

To eliminate this waste, modern pretraining stacks employ chunked cross-entropy (or fused loss kernels such as Liger-Kernel or FlashCrossEntropy). Instead of materializing the entire [b, s, V] logit tensor in HBM, the sequence dimension is divided into smaller chunks (for example, 512 tokens). For each chunk, the GPU projects hidden states to logits, computes the softmax reduction, evaluates the loss, immediately calculates the backward gradient p - y, backpropagates into the hidden state gradient \nabla_h \mathcal{L}, and discards the logit chunk. This reduces peak loss memory from 4.2 GB down to less than 270 MB without altering mathematical results.

Why the Backward Pass Costs Twice the Forward Pass (6ND Rule)

The anatomy of a linear layer

The core computational primitive in transformers is the general matrix multiplication (GEMM). Consider a standard feed-forward or projection layer with weight matrix W \in \mathbb{R}^{D_{\text{in}} \times D_{\text{out}}} operating on an input activation tensor X \in \mathbb{R}^{B \times D_{\text{in}}}, where B = b \times s represents the total batch tokens:

Y = X W

Computing each scalar element of Y requires an inner product between a row of X (length D_{\text{in}}) and a column of W (length D_{\text{in}}), which entails D_{\text{in}} multiplications and D_{\text{in}}\) additions—totaling 2 D_{\text{in}} floating-point operations. Because Y has B \times D_{\text{out}} elements, the forward pass compute is:

\text{FLOPs}_{\text{forward}} = 2 B D_{\text{in}} D_{\text{out}} = 2 \times (\text{tokens}) \times (\text{parameters}) GEMM breakdown of a linear layer: forward evaluation executes 1 GEMM (2ND FLOPs). Backward evaluation executes 2 GEMMs: one multiplying incoming gradients by transposed weights to propagate to inputs (2ND FLOPs), and one multiplying transposed activations by incoming gradients to calculate parameter updates (2ND FLOPs). Total: 6ND FLOPs.

During the backward pass, backpropagation receives the upstream loss gradient G = \frac{\partial \mathcal{L}}{\partial Y} \in \mathbb{R}^{B \times D_{\text{out}}}. To complete the step, the layer must calculate two separate tensor derivatives:

  1. Gradient with respect to input activations (\frac{\partial \mathcal{L}}{\partial X}): To propagate error signals backward to earlier layers, the framework multiplies incoming gradients by the transposed weight matrix: \frac{\partial \mathcal{L}}{\partial X} = G W^\top \quad \text{where } G \in \mathbb{R}^{B \times D_{\text{out}}}, \, W^\top \in \mathbb{R}^{D_{\text{out}} \times D_{\text{in}}} This GEMM produces a [B \times D_{\text{in}}] tensor. Its computational cost is 2 B D_{\text{out}} D_{\text{in}} FLOPs.
  2. Gradient with respect to layer weights (\frac{\partial \mathcal{L}}{\partial W}): To update the model's parameters, the framework multiplies the transposed input activations by the incoming gradients: \frac{\partial \mathcal{L}}{\partial W} = X^\top G \quad \text{where } X^\top \in \mathbb{R}^{D_{\text{in}} \times B}, \, G \in \mathbb{R}^{B \times D_{\text{out}}} This GEMM produces a [D_{\text{in}} \times D_{\text{out}}] parameter gradient tensor. Its computational cost is 2 D_{\text{in}} B D_{\text{out}} FLOPs.

Summing the two backward operations yields:

\text{FLOPs}_{\text{backward}} = 2 B D_{\text{out}} D_{\text{in}} + 2 D_{\text{in}} B D_{\text{out}} = 4 B D_{\text{in}} D_{\text{out}} = 2 \times \text{FLOPs}_{\text{forward}}

Because the backward pass must evaluate two full matrix multiplications for every forward matrix multiplication, the backward pass requires exactly twice the compute of the forward pass. Combining the forward and backward passes gives the fundamental 6ND scaling rule formulated by Kaplan et al. [3] and Hoffmann et al. [4]:

\text{Total FLOPs per Step} = 2 N D + 4 N D = 6 N D

where N is the non-embedding parameter count and D is the number of tokens processed in the batch (explored thoroughly in Lesson 7, Training FLOPs, Time and MFU).

Full activation recomputation (8ND)

In standard training, intermediate activations X are retained in GPU memory from the forward pass until their corresponding backward GEMM executes. However, as derived in Lesson 3 (Training Memory), for long sequences (such as 8,192 tokens), storing activations across all 32 layers requires hundreds of gigabytes of HBM, creating an immediate Out-Of-Memory (OOM) crash [5].

To eliminate this activation memory, systems use activation checkpointing (also called gradient checkpointing). Instead of saving all intermediate tensors, the forward pass saves only the inputs at the boundaries of each transformer layer (or block). During the backward pass, when backpropagation reaches a layer, it re-executes the forward pass for that layer from its cached input, regenerating the intermediate activations immediately before computing \frac{\partial \mathcal{L}}{\partial W} and \frac{\partial \mathcal{L}}{\partial X} [5].

Re-executing the forward pass adds an extra 2ND FLOPs of compute to the training step:

\text{FLOPs with Checkpointing} = 2ND \text{ (forward)} + 2ND \text{ (recompute)} + 4ND \text{ (backward)} = 8ND

Activation recomputation incurs a 33.3% computational overhead (8ND / 6ND = 1.333). In exchange, it slashes activation memory by over 90%, making it possible to train modern 8K-context models on standard hardware.

Which activation retention strategy fits our run?

For pretraining Llama 3.1 8B with sequence length 8,192 on our 256 H100 cluster, uncheckpointed activation storage requires approximately 380 GB per GPU—exceeding device memory by nearly 5×. Conversely, full activation checkpointing adds 33% compute overhead (8ND). The optimal strategy is selective activation checkpointing combined with FlashAttention-3 [6]. FlashAttention never writes the s \times s attention score matrix to HBM, eliminating the quadratic memory term entirely. We checkpoint only the large MLP feed-forward blocks while retaining attention linear projections. This reduces activation memory to under 28 GB per GPU, fitting comfortably within the 80 GB budget while avoiding the full 33% FLOP penalty.

Autograd and Gradient Accumulation in PyTorch

How PyTorch Autograd works

PyTorch features an tape-based automatic differentiation engine called autograd [2]. When a tensor with requires_grad=True participates in an operation, autograd dynamically allocates a node in the computation graph. Each tensor exposes a .grad_fn attribute referencing the backward operation that created it.

When the user invokes loss.backward(), autograd performs the following steps:

  1. Executes a topological sort starting from the loss tensor's .grad_fn to establish backward evaluation order.
  2. Iteratively executes each node's vector-Jacobian product kernel, streaming intermediate gradients to predecessor nodes.
  3. Accumulates parameter gradients into the .grad attribute of leaf tensors using in-place addition: \text{param.grad} \leftarrow \text{param.grad} + \nabla_{\text{param}} \mathcal{L}

Because PyTorch accumulates gradients via addition by default, the training loop must explicitly call optimizer.zero_grad(set_to_none=True) before the next step. Setting gradients to None rather than writing zeros avoids allocating memory buffers and skips memory-write operations across the entire parameter set.

Always mention set_to_none=True when discussing optimizer.zero_grad(). It saves memory bandwidth by freeing the gradient buffers instead of writing millions of FP32 zeros to HBM.

When evaluating validation loss or executing inference, wrapping execution inside with torch.inference_mode(): (or torch.no_grad()) completely disables graph recording. This stops autograd from saving forward activations or creating .grad_fn tracking references, reducing execution latency and memory usage.

Gradient accumulation across micro-batches

In our pretraining scenario, our target global batch size is 512 sequences (\approx 4.19\text{M tokens}). Across 256 GPUs, each GPU must process an effective batch of 512 / 256 = 2\text{ sequences} per optimizer update. Because an 8,192-token sequence with backward state occupies substantial memory, the GPU cannot execute both sequences simultaneously in one forward-backward pass.

We resolve this using gradient accumulation. The per-device micro-batch size is set to b = 1, and the optimizer step is deferred across K = 2 accumulation steps. Figure 7 illustrates this execution timeline.

Execution timeline of gradient accumulation: micro-batches 1 and 2 execute forward and backward passes independently. Each micro-batch loss is divided by accumulation factor K = 2, accumulating gradients into .grad without clearing. After K steps, an all-reduce synchronizes gradients across all 256 GPUs, and optimizer.step() updates the weights.

To compute the mathematically correct average gradient over the global batch, each micro-batch loss must be scaled by 1 / K before calling .backward():

\mathcal{L}_{\text{global}} = \frac{1}{K} \sum_{k=1}^K \mathcal{L}_k \implies \nabla \mathcal{L}_{\text{global}} = \sum_{k=1}^K \nabla \left( \frac{\mathcal{L}_k}{K} \right)

In distributed data parallel setups (Lesson 10, Data Parallelism and All-Reduce), calling model.no_sync() during the first K-1 micro-batches prevents unnecessary gradient communication across the InfiniBand network, triggering the collective all-reduce only on the final micro-batch.

Other Talking Points

If there is extra time at the end of the interview, here are some additional talking points:

  • Loss scaling in mixed precision: When executing backward passes in FP16, small gradient values underflow to zero. While BF16 has an 8-bit exponent matching FP32 and avoids scaling, FP16 requires dynamic loss scaling to shift gradients into representable range (detailed in Lesson 5, Mixed Precision Training - BF16 and FP8).
  • Gradient checkpointing re-entrant vs non-reentrant: Early PyTorch implementations used re-entrant autograd checkpointing, which had issues with hooks and early tensor deallocation. Modern PyTorch uses torch.utils.checkpoint.checkpoint(use_reentrant=False), which integrates natively with autograd graph execution.
  • Fused cross-entropy and loss-head kernels: Chunking the cross-entropy projection across vocabulary dimensions avoids ever writing full [b, s, V] logit tensors to HBM, saving up to 4 GB of activation memory per stream in Llama 3 models.
  • Double backward and gradient penalties: Certain regularization methods (such as gradient penalty in WGANs or Hessian-vector products) require differentiating through the backward graph itself, requiring create_graph=True during the first backward call.
  • Overlap of backward compute and collective communication: In Distributed Data Parallel (DDP), gradient all-reduce communication overlaps asynchronously with the backward pass of earlier layers via backward hooks, hiding inter-node communication latency (Lesson 10, Data Parallelism and All-Reduce).
  • Memory profiling with PyTorch profiler: Using torch.profiler.profile(with_stack=True, profile_memory=True) lets engineers inspect exact allocation and deallocation events for intermediate activations throughout the forward-backward cycle.

Summary

Mind map summarizing the forward and backward passes: step phases, backpropagation arithmetic, cross-entropy gradient, the 6ND FLOP rule, autograd graph recording, and distributed cluster budgeting.
  • A single training step consists of four sequential phases: forward activation evaluation (2ND FLOPs), loss evaluation against vocabulary targets, backward backpropagation (4ND FLOPs), and master weight optimization.
  • The backward pass costs twice the forward pass because each linear layer requires two matrix multiplications: one to propagate gradients to inputs (G W^\top), and one to calculate parameter updates (X^\top G).
  • Standard training requires approximately 6ND FLOPs per token, which increases to 8ND when full activation checkpointing re-evaluates the forward pass during backpropagation.
  • Backpropagation through next-token cross-entropy yields the gradient p - y, pushing probability mass directly toward the target token. Large vocabularies (128,256) require chunked cross-entropy to avoid gigabytes of transient logit allocations.
  • PyTorch autograd dynamically constructs an evaluation graph and accumulates gradients into .grad buffers via in-place addition, requiring optimizer.zero_grad(set_to_none=True) between global steps.
  • On 256 NVIDIA H100 GPUs, pretraining Llama 3.1 8B with a 4M-token global batch takes 2.00 seconds per step at 40% MFU, completing a 1-trillion-token run in 5.5 days (33,800 GPU-hours).
