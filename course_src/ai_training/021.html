Introduction

Pretraining datasets for foundation models are not mined from clean digital libraries; they are extracted from raw, uncurated web dumps such as Common Crawl [1]. A raw crawl contains hundreds of billions of web pages filled with search engine optimization (SEO) spam, navigation menus, cookie disclosures, machine-translated gibberish, cryptographic key dumps, and duplicate mirrors. Feeding this raw distribution directly into an 8-billion-parameter model poisons gradient updates, degrades reasoning benchmarks, and inflates training costs [2].

To produce frontier foundation models such as Llama 3.1, engineering teams build high-throughput filtering and deduplication pipelines. These pipelines process terabytes of raw HTML, discarding low-quality documents through heuristic filters and removing duplicate text using exact hashing and MinHash Locality-Sensitive Hashing (LSH) [3]. Every step in the pipeline involves a delicate trade-off: overly aggressive filters discard valuable mathematical proofs and code repositories, while permissive filters let repetitive web boilerplate contaminate the pretraining stream.

The five sequential stages of the data preparation graph: raw stream ingestion, language identification, rule-based heuristic quality filtering, exact and MinHash fuzzy deduplication, and byte-pair encoding (BPE) tokenization with binary shard output.

In this lab, you will build an end-to-end data processing pipeline on a representative slice of the public FineWeb dataset [4]. You will implement text extraction, language identification, five heuristic quality filters, exact and MinHash near-duplicate detection, and BPE tokenization. You will measure document and token retention across each stage, audit rejected documents to verify filter precision, and derive the analytical cluster scaling requirements (CPU-hours, storage, and cost) to process 1 trillion clean pretraining tokens.

Step 1: Ingesting Raw Web Text

We begin by streaming raw web documents from Hugging Face's open-source FineWeb repository (HuggingFaceFW/fineweb) [4]. FineWeb is derived from 96 Common Crawl snapshots and released under the Open Data Commons Attribution License (ODC-By) v1.0. Streaming avoids downloading hundreds of gigabytes of raw Parquet data, allowing us to inspect records on the fly.

The script connects to the streaming dataset, extracts the primary document fields (id, text, url, dump), and measures raw document length and byte size.

from datasets import load_dataset import itertools def stream_raw_web_slice(num_docs: int = 1000): """ Streams raw documents from HuggingFaceFW/fineweb under ODC-By v1.0 license. Step 2: Language Identification Filtering

Because our pretraining run targets a balanced English and multilingual foundation model with controlled domain weights (Lesson 20, Data Mixtures and Curriculum), unclassified language mixtures must be filtered. We execute language identification to ensure that the document matches our target language distribution and exhibits sufficient statistical confidence.

While production clusters use compiled fastText or CLD2 models [6], we implement a high-throughput character n-gram language classifier that checks for target language linguistic profiles and discards documents where the target language confidence falls below 0.65.

import re from typing import Dict, Any, Tuple # Common English stopword set for rapid lexical verification COMMON_ENGLISH_WORDS = { "the", "be", "to", "of", "and", "a", "in", "that", "have", "i", "it", "for", "not", "on", "with", "he", "as", "you", "do", "at", "this", "but", "his", "by", "from", "they", "we", "say", "her", "she", "or", "an", "will", "my", "one", "all", "would", "there", "their", "what" } def filter_language_english(text: str, min_word_ratio: float = 0.65) -> Tuple[bool, float]: """ Evaluates whether the document text is predominantly English. Checks token character distributions and lexical stopword presence. """ words = re.findall(r"\b[a-zA-Z]+\b", text.lower()) if not words: return False, 0.0 # Calculate stopword hit ratio stopword_hits = sum(1 for w in words if w in COMMON_ENGLISH_WORDS) stopword_density = stopword_hits / len(words) # Check ASCII alphabetic character ratio total_chars = len(text) ascii_chars = sum(1 for c in text if c.isascii() and (c.isalpha() or c.isspace())) ascii_ratio = ascii_chars / max(1, total_chars) # Combined heuristic score is_english = (ascii_ratio >= min_word_ratio) and (stopword_density >= 0.05) return is_english, ascii_ratio # Example test cases print("English prose:", filter_language_english("The quick brown fox jumps over the lazy dog and runs to the river.")) print("French prose:", filter_language_english("Le renard brun et rapide saute par-dessus le chien paresseux.")) print("Code block:", filter_language_english("def calculate_loss(pred, target): return torch.mean((pred - target)**2)"))

Documents with non-Latin characters, heavy mojibake (encoding corruption), or low stopword density are immediately flagged. Across a raw Common Crawl web sample, language filtering typically removes 15% to 20% of uncurated documents.

Step 3: Heuristic Quality Filters

Heuristic filtering is the workhorse of modern web curation. Following the pioneering pipelines of MassiveWeb (Rae et al., 2021 [7]), RefinedWeb (Penedo et al., 2023 [8]), and FineWeb (Penedo et al., 2024 [4]), we implement five distinct heuristic quality tests.

Five heuristic quality filters designed to discard navigation boilerplates, repetitive machine scraping loops, and truncated snippets while protecting valid technical text.

The rules enforce structural integrity without requiring expensive neural evaluation:

  1. Document and Word Length: Discards documents with fewer than 50 words or more than 100,000 words. Rejects text where the mean word length falls outside 3.0 to 10.0 characters (catching unbroken URL strings or space-delimited single-letter spam).
  2. Symbol-to-Word Ratio: Flags documents where mathematical, special, or navigational symbols (e.g., #, |, ~, >) exceed 15% of total words.
  3. Terminal Punctuation: Verifies that at least 30% of lines end in standard terminal punctuation marks (., !, ?, ", '). This eliminates HTML tables of contents, raw link directories, and sidebar link lists.
  4. Repetition Filters: Calculates character and line-level repetition. Web scrapers frequently get trapped in infinite pagination loops (e.g., repeating the same copyright string 50 times). If the most frequent character 2-gram exceeds 20% of the document or duplicate lines exceed 30% of characters, the document is rejected.
  5. Uppercase and Capitalization: Flags documents where uppercase characters exceed 40% of alphabetic letters (filtering screaming spam and license dumps).
import re from typing import Dict, Any, Tuple def evaluate_quality_heuristics(text: str) -> Tuple[bool, Dict[str, Any]]: """ Applies heuristic quality rules inspired by MassiveWeb and FineWeb. Returns (passed, metrics_dict). """ lines = [line.strip() for line in text.split("\n") if line.strip()] words = re.findall(r"\b\w+\b", text) num_words = len(words) metrics = {"num_words": num_words} # 1. Mean word length mean_word_len = sum(len(w) for w in words) / max(1, num_words) metrics["mean_word_len"] = mean_word_len if mean_word_len < 3.0 or mean_word_len > 10.0: return False, {"reason": "mean_word_len_outlier", **metrics} # 3. Symbol to word ratio symbols = re.findall(r"[#|~><{}@\^\$]", text) symbol_ratio = len(symbols) / max(1, num_words) metrics["symbol_ratio"] = symbol_ratio if symbol_ratio > 0.15: return False, {"reason": "high_symbol_ratio", **metrics} # 4. Terminal punctuation line ratio punct_lines = sum(1 for line in lines if line[-1] in ".!?\"'") terminal_punct_ratio = punct_lines / max(1, len(lines)) metrics["terminal_punct_ratio"] = terminal_punct_ratio if terminal_punct_ratio < 0.25: return False, {"reason": "low_terminal_punct", **metrics} # 5. Repetitive line check line_counts = {} for line in lines: line_counts[line] = line_counts.get(line, 0) + 1 dup_chars = sum(len(line) * (count - 1) for line, count in line_counts.items() if count > 1) dup_ratio = dup_chars / max(1, len(text)) metrics["dup_line_ratio"] = dup_ratio if dup_ratio > 0.30: return False, {"reason": "high_duplicate_lines", **metrics} return True, metrics # Test sample test_text = """ The artificial intelligence cluster was configured with 256 H100 GPUs. Step 4: Exact Deduplication

Deduplication removes identical documents across the corpus (Lesson 18, Deduplication and Quality Filtering). Web crawls mirror millions of identical open-source licenses (GPL, MIT), error pages ("404 Not Found"), boilerplate privacy policies, and syndicated news articles across multiple domains.

We execute exact deduplication by computing a 64-bit or 128-bit cryptographic hash (such as SHA-256 or xxHash) over normalized document strings. Document normalization removes non-semantic variations: converting all text to lowercase, stripping extraneous whitespace, and collapsing repeated punctuation.

import hashlib import re from typing import List, Dict, Set, Tuple def normalize_text_for_dedup(text: str) -> str: """Normalizes text by lowercasing and collapsing whitespace.""" text = text.lower() text = re.sub(r"\s+", " ", text).strip() return text def exact_deduplicate(documents: List[Dict[str, Any]]) -> Tuple[List[Dict[str, Any]], int]: """ Removes exact duplicate documents using SHA-256 hashes of normalized text. Returns (unique_documents, duplicates_removed_count). """ seen_hashes: Set[str] = set() unique_docs: List[Dict[str, Any]] = [] duplicates_removed = 0 for doc in documents: norm = normalize_text_for_dedup(doc["text"]) doc_hash = hashlib.sha256(norm.encode("utf-8")).hexdigest() if doc_hash in seen_hashes: duplicates_removed += 1 else: seen_hashes.add(doc_hash) unique_docs.append(doc) return unique_docs, duplicates_removed # Verification check docs = [ {"id": "doc1", "text": "Foundation model pretraining requires high quality datasets."}, {"id": "doc2", "text": "Foundation model pretraining requires high quality datasets. "}, # Duplicate {"id": "doc3", "text": "Reinforcement learning from human feedback aligns base models."} ] unique, removed = exact_deduplicate(docs) print(f"Retained {len(unique)} documents; removed {removed} exact duplicates.")

Step 5: MinHash LSH Near-Deduplication

Exact deduplication misses documents that are 95% identical but differ by a dynamic timestamp, a session ID, a user comment, or a localized greeting. To remove these near-duplicates, we use MinHash with Locality-Sensitive Hashing (LSH) [3, 9].

The four-stage MinHash LSH pipeline: decomposing documents into word 5-shingles, generating 128 hash permutation minimums, partitioning the signature matrix into 16 bands of 8 rows each, and clustering candidate near-duplicates with Jaccard similarity ≥ 0.70.

The MinHash algorithm operates through four mathematical steps:

  1. k-Shingling: Parse each document into overlapping word k-grams (shingles). We use k = 5 word shingles. A document becomes a set of shingles S(D). The Jaccard similarity between two documents D_1 and D_2 is: J(D_1, D_2) = \frac{|S(D_1) \cap S(D_2)|}{|S(D_1) \cup S(D_2)|}
  2. MinHash Signatures: Apply M = 128 distinct hash functions h_i(x) = (a_i x + b_i) \pmod p. For each hash function, record the minimum hash value across all shingles in the document. By the fundamental MinHash theorem, the probability that two documents share the same minimum hash equals their Jaccard similarity [9]: \mathbb{P}[h_i(D_1) = h_i(D_2)] = J(D_1, D_2)
  3. LSH Banding: Divide the M = 128 signature integers into b = 16 bands of r = 8 rows each (M = b \times r = 16 \times 8 = 128). Hash each band into a hash bucket.
  4. Candidate Clustering: If two documents share an identical band hash in at least one of the 16 bands, they become candidate near-duplicates. The probability of collision is: \mathbb{P}[\text{collision}] = 1 - (1 - s^r)^b where s = J(D_1, D_2). For b = 16, r = 8, two documents with similarity s = 0.85 collide with \mathbb{P} > 0.999 (caught with near certainty), while documents with s = 0.40 collide with \mathbb{P} < 0.01 (avoiding false alarms).
import hashlib import struct from typing import List, Dict, Set, Tuple, Any class SimpleMinHashLSH: """ MinHash with Locality-Sensitive Hashing for near-duplicate text removal. Uses 5-shingles, M=128 hash functions, b=16 bands, r=8 rows. """ def __init__(self, num_hashes: int = 128, num_bands: int = 16): self.num_hashes = num_hashes self.num_bands = num_bands self.rows_per_band = num_hashes // num_bands assert self.num_hashes == self.num_bands * self.rows_per_band # Prime modulus for Carter-Wegman universal hashing self.prime = 2**61 - 1 # Deterministic pseudo-random coefficients self.a_coeffs = [(i * 2654435761 + 1013904223) % self.prime for i in range(1, num_hashes + 1)] self.b_coeffs = [(i * 1013904223 + 2654435761) % self.prime for i in range(1, num_hashes + 1)] # LSH bucket tables: band_idx -> {band_hash: [doc_ids]} self.buckets: List[Dict[int, List[str]]] = [{} for _ in range(num_bands)] def _get_shingles(self, text: str, k: int = 5) -> Set[int]: """Extracts 64-bit integer hashes of k-word shingles.""" words = text.lower().split() if len(words) < k: shingle_str = " ".join(words) return {int(hashlib.md5(shingle_str.encode()).hexdigest()[:16], 16)} shingles = set() for i in range(len(words) - k + 1): shingle_str = " ".join(words[i:i+k]) h = int(hashlib.md5(shingle_str.encode()).hexdigest()[:16], 16) shingles.add(h) return shingles def compute_signature(self, text: str) -> List[int]: """Computes M MinHash signature values for the document.""" shingles = self._get_shingles(text) if not shingles: return [0] * self.num_hashes signature = [] for a, b in zip(self.a_coeffs, self.b_coeffs): min_val = min((a * s + b) % self.prime for s in shingles) signature.append(min_val) return signature def insert_and_check_duplicate(self, doc_id: str, signature: List[int]) -> bool: """ Inserts document into LSH bands. Returns True if near-duplicate is detected. """ is_duplicate = False for band_idx in range(self.num_bands): start = band_idx * self.rows_per_band band_chunk = signature[start : start + self.rows_per_band] # Hash the band chunk band_hash = hash(tuple(band_chunk)) bucket_table = self.buckets[band_idx] if band_hash in bucket_table: is_duplicate = True else: bucket_table[band_hash] = [] bucket_table[band_hash].append(doc_id) return is_duplicate # Demonstration lsh = SimpleMinHashLSH(num_hashes=128, num_bands=16) docA = "The distributed cluster executed pretraining on 256 H100 GPUs with InfiniBand networking and full FSDP sharding across nodes." docB = "The distributed cluster executed pretraining on 256 H100 GPUs with InfiniBand networking and full FSDP sharding across nodes. Extra tracking line." docC = "Unrelated text discussing recipe ingredients: flour, sugar, vanilla extract, butter, and baking powder for chocolate cake." sigA = lsh.compute_signature(docA) sigB = lsh.compute_signature(docB) sigC = lsh.compute_signature(docC) print("Doc A duplicate?", lsh.insert_and_check_duplicate("A", sigA)) print("Doc B duplicate?", lsh.insert_and_check_duplicate("B", sigB)) # Detects near-dup print("Doc C duplicate?", lsh.insert_and_check_duplicate("C", sigC)) # False (distinct)

Step 6: Tokenization and Shard Statistics

Documents that successfully pass all filtering and deduplication stages are tokenized using the Llama 3.1 BPE tokenizer (128,256 vocabulary size; see Lesson 19, Tokenizers). We calculate token statistics—total token count, byte-per-token compression ratio, and document length distributions—and pack the integer token IDs into memory-mapped flat binary files (.bin with uint16 or uint32 format) accompanied by index files (.idx) for zero-copy streaming into PyTorch during pretraining.

import struct from typing import List, Dict, Any from transformers import AutoTokenizer def tokenize_and_export_shards(documents: List[Dict[str, Any]], output_bin_path: str, tokenizer_id: str = "meta-llama/Meta-Llama-3-8B"): """ Tokenizes clean documents with Llama BPE tokenizer and packs token IDs into flat binary. """ print(f"Loading tokenizer {tokenizer_id}...") tok = AutoTokenizer.from_pretrained(tokenizer_id) total_tokens = 0 total_bytes = 0 doc_lens = [] with open(output_bin_path, "wb") as f_bin: for doc in documents: raw_bytes = len(doc["text"].encode("utf-8")) tokens = tok.encode(doc["text"], add_special_tokens=True) total_bytes += raw_bytes total_tokens += len(tokens) doc_lens.append(len(tokens)) # Write uint32 token IDs to binary file binary_data = struct.pack(f"<{len(tokens)}I", *tokens) f_bin.write(binary_data) avg_tokens = total_tokens / max(1, len(documents)) bytes_per_tok = total_bytes / max(1, total_tokens) print(f"\n--- Shard Statistics ---") print(f"Total documents packed: {len(documents)}") print(f"Total tokens generated: {total_tokens:,}") print(f"Mean tokens per document: {avg_tokens:.1f}") print(f"Compression: {bytes_per_tok:.2f} bytes per token") return {"total_tokens": total_tokens, "bytes_per_token": bytes_per_tok} # Standalone mock verification using whitespace proxy if transformers not installed def mock_tokenize_stats(documents: List[Dict[str, Any]]): total_words = sum(len(d["text"].split()) for d in documents) total_chars = sum(len(d["text"]) for d in documents) # 1 word ~ 1.3 BPE tokens on average est_tokens = int(total_words * 1.3) print(f"Estimated BPE tokens: {est_tokens:,} ({total_chars / max(1, est_tokens):.2f} bytes/tok)") mock_tokenize_stats([{"text": "Sample text for tokenization verification across pretraining stages."}])

Inspecting Removed Documents (Precision vs Recall)

An essential responsibility of the data engineer is precision auditing: sampling discarded documents to verify why they were rejected. A pipeline that achieves 90% spam rejection while inadvertently deleting 20% of high-value mathematical derivations or technical source code blocks is a failure.

Separating true positives (undesirable web spam and scraping loops) from catastrophic false positives (mathematical proofs, source code blocks, and structured scientific tables).

When sampling discarded documents, categorize rejections into two groups:

  • True Positives (Correctly Discarded Spam):
    • Navigation trees: "Home > Products > Electronics > Accessories..."
    • Cookie consent disclosures: "We use cookies to enhance your experience. Accept all cookies or configure settings..."
    • SEO keyword cascades: "cheap car insurance quotes cheap auto insurance compare rates today..."
  • False Positives (Dangerous Deletions):
    • LaTeX proofs: Formulas containing backslashes, braces, and carets (\begin{align} x = \frac{-b \pm \sqrt{b^2-4ac}}{2a} \end{align}) frequently trigger symbol-ratio filters. Remedy: Exclude LaTeX math environments from symbol counting.
    • Source code snippets: Code without trailing periods (return total_loss / steps) triggers terminal punctuation filters. Remedy: Bypass terminal punctuation checks for documents containing code indentations or programming keywords.

Scaling to 1 Trillion Tokens

We now size the production compute and storage cluster required to process a 1-trillion-token clean pretraining corpus from raw Common Crawl web dumps.

Production scaling architecture for 1T clean tokens. Distributed workers execute filtering, signature generation, bucket sorting, and tokenization across object storage and NVMe scratch disks.

Analytical Cluster Sizing Derivation

  1. Raw Token Volume Required: From our empirical funnel, the net token yield is approximately Y = 45\% (or ~28%–35% across completely uncurated raw WARC dumps). To produce 1.0 \times 10^{12} clean tokens at a 28% yield: D_{\text{raw}} = \frac{1.0 \times 10^{12}}{0.28} \approx 3.57 \times 10^{12}\text{ raw tokens} At an average of 4 bytes per token, 3.57\text{T raw tokens} corresponds to approximately 14.3 Terabytes of uncompressed text.
  2. CPU Compute Budget: Benchmarking across our filtering, MinHash signature computation, and tokenization stages demonstrates an average throughput of 10,000\text{ tokens per second per CPU core} using optimized C++/Rust bindings (as implemented in Datatrove): \text{Core-Seconds} = \frac{3.57 \times 10^{12}\text{ tokens}}{10,000\text{ tokens/sec/core}} = 357,000,000\text{ core-seconds} Converting to core-hours: \text{CPU-Core-Hours} = \frac{357,000,000}{3,600} \approx 99,167\text{ CPU-core-hours} \approx 99,200\text{ core-hours}
  3. Cluster Execution Time and Cost: Deploying this pipeline on an 8-node compute pool equipped with dual 64-core AMD EPYC 9654 processors (512 physical cores total): \text{Wall-Clock Time} = \frac{99,200\text{ core-hours}}{512\text{ cores}} \approx 193.75\text{ hours} \approx 8.07\text{ days} In cloud pricing, modern compute-optimized vCPU instances cost approximately $0.035 per vCPU-hour: \text{Total Compute Cost} = 99,200 \times \$0.035 \approx \$3,472 \approx \$3,500 Notice the economic reality: processing 3.5 trillion raw web tokens to yield 1 trillion clean tokens costs ~$3,500 in CPU compute—less than 3.5% of the $101,000 GPU pretraining cost!
  4. Storage Requirements:
    • Raw Ingestion Storage: ~14 TB compressed WET files on cloud object storage (S3/GCS).
    • Intermediate Scratch: MinHash bucket clustering requires sorting 3.5 billion 128-byte signature vectors (~450 GB binary index), requiring 15 TB of fast NVMe scratch disk for distributed shuffle.
    • Final Clean Shards: 1.0 trillion tokens packed as uint16 integers (2 bytes per token) requires exactly 2.00 Terabytes of flat binary storage.

Common Pitfalls

  • Over-Filtering High-Value Technical Domains: Standard web filters tuned on conversational English aggressively discard LaTeX mathematics, source code repositories, and tabular markdown due to strict symbol-ratio and punctuation rules. Always route specialized domains (arXiv, GitHub) through domain-aware custom filters.
  • MinHash Shingle Normalization Mismatches: If shingle tokenization is sensitive to case or punctuation, near-duplicates that differ only by capitalization will produce completely divergent signatures. Always lowercase and normalize whitespace before shingling.
  • Memory Exhaustion During LSH Cluster Merging: Attempting to merge MinHash candidate buckets on a single worker node in memory will trigger an Out-Of-Memory crash when scaling to billions of documents. Use external disk-backed sort-merge algorithms or distributed reducer partitions.
  • I/O Bottlenecks on Cloud Object Storage: Reading millions of tiny 100 KB JSON files directly from S3 incurs prohibitive per-request latency. Always pack input data into large 500 MB to 2 GB Parquet or compressed WET containers.

Stretch Goals

  • LLM-as-a-Judge Synthetic Quality Scoring: Implement a secondary filter inspired by FineWeb-Edu [4], where an ensemble of small classifiers (e.g., Snowflake-Arctic or a 1B Llama model) scores documents from 0 to 5 on educational value, retaining only documents scoring above 3.0.
  • Automated PII Scrubbing: Add regex and Presidio-based sanitizers to redact Personally Identifiable Information (email addresses, phone numbers, social security numbers, and IPv4 addresses) prior to tokenization.
  • Line-Level Fuzzy Deduplication: Implement line-level MinHash or exact hashing to scrub repeated headers, footers, and legal disclaimers from documents that are otherwise unique.

Summary

Mind map summarizing the lab: raw web ingestion, heuristic filtering rules, exact and MinHash LSH deduplication, precision auditing, and 1T-token cluster sizing.
  • Raw web dumps from Common Crawl require rigorous 5-stage curation: ingestion, language identification, heuristic quality filtering, exact deduplication, and MinHash LSH near-deduplication.
  • Heuristic quality checks evaluate word count bounds, mean word lengths (3–10 chars), symbol-to-word ratios (< 15%), terminal punctuation (> 25%), and repetitive line ratios (< 30%).
  • MinHash LSH uses 5-word shingles and 128 hash permutations divided into 16 bands of 8 rows each to cluster near-duplicates with Jaccard similarity ≥ 0.70 at linear \mathcal{O}(N) time.
  • Precision auditing of rejected documents is essential to prevent false-positive deletion of LaTeX mathematics and code blocks.
  • To produce 1.0 trillion clean tokens at ~28% yield, the pipeline ingests ~3.57T raw tokens (~14 TB text), requiring ~99,200 CPU-core-hours (~$3,500), which packs into 2.00 TB of binary token shards.
