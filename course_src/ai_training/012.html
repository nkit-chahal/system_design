Introduction

In Lesson 10, Data Parallelism and All-Reduce, and Lesson 11, ZeRO and FSDP, we explored data parallelism and state sharding. Sharded data parallelism scales training across hundreds of GPUs by distributing optimizer states, gradients, and model parameters. However, data parallelism partitions the training workload exclusively along the batch dimension. When scaling modern transformer models, two distinct engineering barriers arise that data parallelism cannot resolve alone [1, 2]:

  1. The Parameter and GEMM Scale Barrier: For models with 70 billion or more parameters, individual weight matrices are too massive for efficient single-device matrix multiplication, and single-layer working memory constraints cause out-of-memory spikes. To accelerate computation and fit layer weights, individual weight matrices must be partitioned across multiple GPUs. This is Tensor Parallelism (TP) [1].
  2. The Context Length Barrier: As training sequences extend from 8,192 tokens to 32,768, 131,072, or 1 million tokens, intermediate attention activations scale quadratically (\mathcal{O}(s^2)) or linearly with FlashAttention, demanding hundreds of gigabytes per sequence [2, 3]. To prevent activation memory exhaustion on long contexts, the sequence must be sharded across cooperating GPUs. This is achieved via Sequence Parallelism (SP) within layers and Context Parallelism (CP) across layers [2, 3, 4].
Architecture of Megatron-LM Tensor Parallelism across self-attention and MLP blocks. Linear projections are split column-wise or row-wise. In the forward pass, each layer executes two all-reduces. In the backward pass, backpropagation through column-parallel projections adds two additional all-reduces, totaling four all-reduce collectives per layer per step.

While inference systems use tensor parallelism purely to reduce serving latency (see Inference Lesson 18, Tensor Parallelism), training transforms the communication physics of tensor parallelism. In training, the backward pass requires an identical set of collective operations to propagate input gradients, doubling the communication frequency to four all-reduces per transformer layer [1]. Because these collective operations are synchronous and blocking, tensor parallelism is strictly bound to ultra-high-speed intra-node NVLink interconnects [1].

In this lesson, we break down Megatron-LM tensor parallelism in training, examine why backpropagation doubles the all-reduce volume, analyze how sequence parallelism eliminates activation redundancy with zero communication penalty, study Ring Attention and DeepSpeed-Ulysses for context parallelism, prove why TP must never cross node boundaries, and determine whether our 8B pretraining run requires TP or CP.

Clarifying the Problem

In distributed training architecture interviews, questions surrounding multi-dimensional parallelism test whether a candidate understands the boundaries between batch, intra-layer, and sequence distribution. Here is how a discussion unfolds:

Candidate: What model architecture, parameter scale, and context length are we pretraining?
Interviewer: We are pretraining a model with the Llama 3.1 8B architecture—8.03 billion parameters across 32 transformer layers, hidden dimension 4,096, 32 query heads, 8 KV heads. The context length is 8,192 tokens.

Candidate: What cluster infrastructure and interconnects are provisioned?
Interviewer: We have 256 NVIDIA H100 80 GB SXM GPUs arranged across 32 nodes (8 GPUs per node). Inside each node, GPUs communicate via NVLink at 900 GB/s per GPU. Across nodes, each node connects through 8 InfiniBand NDR NICs providing 400 Gb/s (50 GB/s) per GPU.

Candidate: What is the global batch size and target hardware efficiency?
Interviewer: The global batch size is 512 sequences of 8,192 tokens (~4 million tokens). We target at least 40% Model FLOPs Utilization (MFU).

Candidate: Should we enable Tensor Parallelism of degree 2 or 4 within each node, or should we enable Context Parallelism for the 8,192-token sequences?
Interviewer: That is the central question. Can you quantify the communication latency if we turn on TP=8 on this 8B model, how does it compare to FSDP alone, and at what model size or context length do TP and CP become mandatory?

The question underneath is: How do Tensor, Sequence, and Context Parallelism interact with GPU compute kernels and network bandwidth, why does backpropagation double TP communication, and why is TP unnecessary for 8B models at 8K context but essential for 70B models?

Tensor Parallelism in Training: The Backward Pass Multiplier

Column and row parallel matrix decomposition

Tensor parallelism, formulated by Shoeybi et al. in Megatron-LM [1], shards the weight matrices of linear projections within each transformer layer across \text{TP} GPUs. Linear layers in transformers are organized in pairs: the Self-Attention block projects inputs via W_q, W_k, W_v followed by output projection W_{\text{out}}; the MLP block projects via W_{\text{gate}}, W_{\text{up}} followed by down projection W_{\text{down}} [1].

Megatron-LM alternates between ColumnParallel and RowParallel linear layers to minimize communication [1]:

  • ColumnParallel Linear: The weight matrix A \in \mathbb{R}^{h \times d} is split along its column (output) dimension into \text{TP} shards: A = [A_1, A_2, \dots, A_{\text{TP}}]. The input activation tensor X \in \mathbb{R}^{s \times b \times h} is replicated across all TP workers. Each worker evaluates: Y_i = X A_i In the forward pass, this requires zero communication; each worker produces a disjoint slice of the output channels [1].
  • RowParallel Linear: The weight matrix B \in \mathbb{R}^{d \times h} is split along its row (input) dimension into \text{TP} shards: B = [B_1; B_2; \dots; B_{\text{TP}}]. The input to this layer is the column-split output Y_i. Each worker computes a local matrix product Z_i = Y_i B_i. Because matrix multiplication is bilinear: Z = X A B = \sum_{i=1}^{\text{TP}} Y_i B_i = \sum_{i=1}^{\text{TP}} Z_i To produce the full output Z before adding the residual connection, the workers must sum their local results. In the forward pass, this requires one all-reduce collective across the TP group [1].

In inference, this pair requires exactly one all-reduce. In a complete transformer layer (Self-Attention + MLP), the forward pass executes exactly 2 all-reduces per layer: one after W_{\text{out}} and one after W_{\text{down}} (see Inference Lesson 18, Tensor Parallelism).

Why the backward pass doubles all-reduces

Engineers transitioning from inference serving to model training frequently overlook the communication demands of backpropagation. In training, gradients must be propagated backward through the network layers using the chain rule of calculus [1].

Let us examine what occurs when backpropagating through RowParallel and ColumnParallel layers:

1. Backpropagation through RowParallel Linear (W_{\text{down}} or W_{\text{out}})

The input to the backward pass is the upstream gradient \partial \mathcal{L} / \partial Z. Because the forward pass concluded with an all-reduce, \partial \mathcal{L} / \partial Z is already present identically on all TP workers [1]. The gradient with respect to the local input activation slice Y_i is:

\frac{\partial \mathcal{L}}{\partial Y_i} = \left(\frac{\partial \mathcal{L}}{\partial Z}\right) B_i^\top

Each worker computes this matrix multiplication locally using its local weight shard B_i. No communication is required in the backward pass of a RowParallel layer.

2. Backpropagation through ColumnParallel Linear (W_q, W_k, W_v or W_{\text{gate}}, W_{\text{up}})

The input activation X was fed identically into all \text{TP} shards during the forward pass. According to the multivariable chain rule, the gradient of the loss with respect to input X is the sum of partial gradients flowing from all column shards [1]:

\frac{\partial \mathcal{L}}{\partial X} = \sum_{i=1}^{\text{TP}} \left(\frac{\partial \mathcal{L}}{\partial Y_i}\right) A_i^\top

Each worker evaluates its local product (\partial \mathcal{L} / \partial Y_i) A_i^\top. To assemble the complete gradient \partial \mathcal{L} / \partial X feeding back into the preceding residual addition and LayerNorm, the workers must execute an all-reduce collective (sum) across the TP group [1]!

Total collective count in training

Because RowParallel requires an all-reduce in forward, and ColumnParallel requires an all-reduce in backward, every transformer layer executes [1]:

  • Self-Attention Block: 1 forward all-reduce + 1 backward all-reduce = 2 all-reduces
  • MLP Block: 1 forward all-reduce + 1 backward all-reduce = 2 all-reduces

Total per layer: 4 all-reduces per transformer layer per training step. For our 32-layer Llama 3.1 8B model, a training step with tensor parallelism executes 32 \times 4 = 128 blocking all-reduce operations. For an 80-layer 70B model, it executes 80 \times 4 = 320 all-reduce operations per step!

Sequence Parallelism: Eliminating Activation Redundancy

The activation memory bottleneck in standard TP

While standard tensor parallelism shards the weight matrices of attention projections and MLP layers by \text{TP}, it leaves LayerNorm, RMSNorm, and Dropout unsharded [2]. In standard Megatron TP, every GPU in the TP group holds an identical copy of the full sequence activation tensor [s, b, h] across every LayerNorm and residual connection.

As derived in Lesson 3, Training Memory, intermediate forward activations stored for the backward pass scale with sequence length s. For an 8,192-token sequence on Llama 3.1 8B, uncheckpointed linear activations consume approximately 36.5 GB per GPU [2]. In standard TP, the activations of LayerNorm and Dropout regions remain duplicated across all GPUs in the TP group, wasting immense High Bandwidth Memory.

The Megatron-LM Sequence Parallelism insight

In 2022, Korthikanti et al. introduced Sequence Parallelism (SP) to eliminate this duplication [2]. They observed that LayerNorm, RMSNorm, and Dropout are strictly element-wise or token-independent operations: normalizations compute statistics across the hidden dimension h independently for each token position, with zero cross-token interactions [2].

Megatron Sequence Parallelism shards LayerNorm and Dropout along the sequence dimension ([s / TP, b, h]). The RowParallel All-Reduce is split into a Reduce-Scatter, feeding the sequence shard directly to LayerNorm. Before ColumnParallel projections, an All-Gather reconstructs the full sequence. Total communication volume is identical to All-Reduce, eliminating activation duplication with zero communication penalty.

Instead of replicating [s, b, h] across all workers, Sequence Parallelism partitions the sequence dimension s across the \text{TP} GPUs in non-tensor-parallel regions. Each GPU processes only [s / \text{TP}, b, h] tokens through LayerNorm and Dropout [2]:

  1. Replacing Forward All-Reduce with Reduce-Scatter: At the output of a RowParallel layer (W_{\text{down}} or W_{\text{out}}), each worker holds local partial sum Z_i \in \mathbb{R}^{s \times b \times h}. Instead of executing an all-reduce to produce the full [s, b, h] tensor on all ranks, workers execute a reduce-scatter collective along the sequence dimension. Each worker receives only its assigned sequence partition [s / \text{TP}, b, h] [2].
  2. Local LayerNorm: Each worker evaluates RMSNorm and Dropout strictly on its local sequence shard of size [s / \text{TP}, b, h]. Activation memory saved for backpropagation is reduced by a factor of \text{TP}!
  3. Replacing Forward Input Replication with All-Gather: Before entering the next ColumnParallel layer (W_q, W_k, W_v or W_{\text{gate}}, W_{\text{up}}), workers must restore the full sequence [s, b, h]. They execute an all-gather collective along the sequence dimension [2].

Zero communication penalty

Does replacing all-reduces with reduce-scatter and all-gather increase network traffic? Recall the fundamental ring collective decomposition from Lesson 10:

\text{Traffic}_{\text{all-reduce}} = \text{Traffic}_{\text{reduce-scatter}} + \text{Traffic}_{\text{all-gather}} = \frac{\text{TP} - 1}{\text{TP}} M + \frac{\text{TP} - 1}{\text{TP}} M = 2 \frac{\text{TP} - 1}{\text{TP}} M

The communication volume of one reduce-scatter plus one all-gather is mathematically identical to the communication volume of a single all-reduce [2]. Sequence parallelism incurs zero extra communication volume while slashing LayerNorm and residual activation memory by a factor of \text{TP}. Consequently, in modern training systems such as Megatron-LM and TorchTitan, Sequence Parallelism is always enabled whenever Tensor Parallelism is active [2, 5].

Context Parallelism for Ultra-Long Sequences

While Megatron Sequence Parallelism shards LayerNorm and Dropout within a tensor-parallel node, it still gathers the full sequence length [s, b, h] inside self-attention. When pretraining or fine-tuning models on ultra-long sequences—such as 32,768, 131,072, or 1 million tokens—the self-attention computation and KV activation footprint exceed single-GPU capacity [3, 4]. To shard the sequence dimension across layers and across nodes, modern systems employ Context Parallelism (CP) [3, 4].

1. Ring Attention

Developed by Liu et al., Ring Attention distributes long sequences across a logical ring of P GPUs, computing exact self-attention without ever materializing the full sequence on any single device [3]:

Ring Attention partitions a sequence of length s into P blocks across a ring of GPUs. Each GPU holds its local Query block stationary while Key and Value blocks circulate peer-to-peer around the ring. Attention computation for block k is fully overlapped with the transmission of block k+1.
  • Partitioning: The input sequence of length s is split into P blocks of length s / P. GPU i computes local query Q_i, key K_i, and value V_i tensors of shape [s / P, b, h] [3].
  • Stationary Queries, Circulating KV: Each GPU keeps its query block Q_i resident in local memory throughout the layer. In contrast, key and value blocks are circulated around the ring [3].
  • Pipelined Overlap: At step k = 0, GPU i computes attention between Q_i and its local K_i, V_i using FlashAttention. Concurrently, it sends K_i, V_i to rank i+1 and receives from rank i-1 over peer-to-peer CUDA streams [3]. At step k = 1, it evaluates attention against the newly arrived block while circulating the block to the next rank.
  • Online Softmax Rescaling: Ring Attention maintains running maximum and sum statistics (the online softmax algorithm of FlashAttention), rescaling partial attention accumulators as new blocks arrive [3].

So long as the compute time for a block of size s / P exceeds the peer-to-peer network transfer time, Ring Attention completely hides communication latency, enabling context length to scale linearly with cluster size up to millions of tokens [3].

2. DeepSpeed-Ulysses

An alternative context-parallel architecture is DeepSpeed-Ulysses, introduced by Jacobs et al. [4]:

DeepSpeed-Ulysses partitions input sequences along the sequence dimension ([s / P, H, d]). Before self-attention, an all-to-all collective transposes the tensor into head-parallel form ([s, H / P, d]). Local FlashAttention evaluates full-context attention for local heads, followed by an inverse all-to-all collective to restore sequence partitioning.
  1. Sequence Partition: Outside self-attention, activations are partitioned along the sequence dimension: each GPU holds [s / P, H, d], where H is total attention heads and d is head dimension [4].
  2. All-to-All Transpose: Before self-attention, workers execute an all_to_all collective communication. This transposes the tensor layout from sequence-sharded [s / P, H, d] to head-sharded [s, H / P, d] [4].
  3. Local Full-Context Attention: Each GPU now possesses the complete sequence length s, but only for a subset of attention heads H / P. Each GPU evaluates standard FlashAttention over the full context length independently with zero communication [4].
  4. Inverse All-to-All: After attention out-projection, a second all_to_all collective redistributes the tensor back from head-sharded [s, H / P, d] to sequence-sharded [s / P, H, d] [4].

The Grouped-Query Attention (GQA) constraint

DeepSpeed-Ulysses provides exceptional throughput on high-bandwidth networks because all-to-all collectives are highly optimized. However, Ulysses imposes a rigid architectural constraint: the number of attention heads H (and key-value heads H_{\text{kv}}) must be evenly divisible by the Ulysses parallelism degree P [4].

For modern models employing Grouped-Query Attention such as Llama 3.1 8B, the architecture provides 32 query heads but only 8 KV heads (H_{\text{kv}} = 8). Consequently, the maximum Ulysses context-parallel degree is P = 8. Scaling beyond 8 GPUs for context parallelism requires Ring Attention or hybrid Ulysses-Ring combinations [4].

Network Physics: Why TP Stays Inside a Node

The blocking nature of Tensor Parallelism

Unlike data parallelism (where gradient communication overlaps with the backward pass) or pipeline parallelism (which operates across layer boundaries), tensor parallelism is strictly synchronous and blocking [1]. When a RowParallel projection computes its local GEMM, the subsequent activation function, LayerNorm, or residual addition cannot execute until the all-reduce completes. There is zero computation available to hide the all-reduce latency [1].

Comparison of 128 blocking all-reduces per step for Llama 3.1 8B. On intra-node NVLink (900 GB/s), all-reduces require only 16.7 ms total (< 0.7% of step time). Over inter-node InfiniBand (50 GB/s), network latency and bandwidth limits explode total stall time to 300.6 ms (and over 1.5 seconds for 70B), causing severe MFU degradation.

Worked numbers: NVLink versus InfiniBand

Let us calculate the exact communication time for Tensor Parallelism on our Llama 3.1 8B model. Micro-batch size is b = 1, sequence length is s = 8,192, hidden dimension is h = 4,096. The activation tensor passed to each all-reduce has shape [8,192, 1, 4,096], comprising 33,554,432 elements. In BF16 (2 bytes/element):

M = 33,554,432 \times 2\text{ bytes} = 67,108,864\text{ bytes} \approx 67.11\text{ MB} \quad (64.0\text{ MiB})

For \text{TP} = 8, the data transferred per rank during one all-reduce is:

\text{Traffic per All-Reduce} = 2 \times \frac{8 - 1}{8} \times 67.11\text{ MB} = 1.75 \times 67.11\text{ MB} \approx 117.44\text{ MB}

Across all 32 transformer layers, executing 4 all-reduces per layer yields 128 all-reduce operations per training step. Total data transferred per GPU per step is:

\text{Total TP Traffic} = 128 \times 117.44\text{ MB} \approx 15,032\text{ MB} \approx 15.03\text{ GB}

Now compare execution over our two physical interconnects:

  1. Over Intra-Node NVLink (900 GB/s bus bandwidth per GPU): T_{\text{all-reduce, NVLink}} = \frac{117.44\text{ MB}}{900\text{ GB/s}} \approx 0.130\text{ ms} = 130\ \mu\text{s} Adding ~10 \mu\text{s} kernel launch and barrier latency, each all-reduce completes in ~140 \mu\text{s}. Across all 128 operations: T_{\text{total, NVLink}} = 128 \times 0.140\text{ ms} \approx 17.9\text{ ms} Against our total step compute time of ~2,660 ms (2.66 s), 17.9 ms represents less than 0.7% overhead. NVLink absorbs the communication seamlessly.
  2. Over Inter-Node InfiniBand NDR (400 Gb/s = 50 GB/s line rate per GPU): T_{\text{all-reduce, IB}} = \frac{117.44\text{ MB}}{50\text{ GB/s}} \approx 2.349\text{ ms} Adding inter-node switch traversals (~20 \mu\text{s}), each all-reduce takes ~2.37 ms. Across 128 operations: T_{\text{total, IB}} = 128 \times 2.37\text{ ms} \approx 303.4\text{ ms} Because each operation blocks GPU execution, the GPUs sit completely idle for over 300 ms per step!

For a 70B model with 80 layers and hidden dimension 8,192, total TP traffic reaches 75.16 GB per step across 320 all-reduces. Over InfiniBand, this introduces 1,503 ms (1.5 seconds) of pure, un-overlapped stall time per step. This proves the universal rule of distributed LLM systems: Tensor Parallelism must be strictly confined within a single node over NVLink [1, 2].

Do we need TP or CP for our pretraining run?

Figure 7 summarizes the architectural decision matrix for distributed training.

Decision matrix for distributed LLM training. Models below 13B parameters at context lengths up to 8,192 tokens achieve peak efficiency using FSDP / HSDP alone with TP=1 and CP=1. Tensor Parallelism (TP=8) is reserved for models exceeding 70B parameters. Context Parallelism (CP=4 to 8) is required when context lengths extend to 32K–128K+ tokens.

For our running pretraining scenario—Llama 3.1 8B at sequence length 8,192 on 256 H100 GPUs:

  1. We do NOT need Tensor Parallelism (\text{TP} = 1): As established in Lesson 11, ZeRO and FSDP, Hybrid Sharded Data Parallelism (HSDP) partitions model and optimizer states across the 8 GPUs in each node, reducing static memory to 16.06 GB per GPU. Combined with FlashAttention and activation checkpointing, activations for an 8,192-token sequence require under 2.5 GB. Total memory per GPU is under 20 GB, fitting easily within our 80 GB budget. Enabling TP would fragment matrix multiplications into tiny GEMMs, add 128 blocking all-reduces, and degrade our target 40% MFU.
  2. We do NOT need Context Parallelism (\text{CP} = 1): At 8,192 tokens, FlashAttention computes attention without materializing the quadratic s \times s attention matrix, keeping peak attention memory under 2 GB per GPU. Context parallelism introduces peer-to-peer or all-to-all communication overhead that is entirely unnecessary at 8K context.

Our optimal configuration is pure HSDP (\text{shard} = 8, \text{replicate} = 32) with TP=1 and CP=1. If the team subsequently scales to Llama 3.1 70B, we will configure TP=8 across NVLink and PP/FSDP across nodes. If we extend context length to 128K tokens, we will activate CP=8 via Ring Attention.

Other Talking Points

If there is extra time at the end of the interview, here are some additional talking points:

  • Vocabulary Parallelism: How the output projection and cross-entropy loss are parallelized by sharding the 128,256-token vocabulary across TP ranks, computing local logits and cross-entropy loss with an all-reduce across scalar loss values [1].
  • Tensor Parallelism and GEMM Efficiency: Why small models suffer under high TP degrees: splitting a 4,096-wide matrix across TP=8 yields 512-wide GEMMs, dropping below the tile size needed to saturate H100 Tensor Cores.
  • Zigzag Ring Attention: Advanced Ring Attention schedules that alternate causal masking directions to achieve 2× higher computation efficiency on autoregressive causal attention [3].
  • DeepSpeed-Ulysses vs Ring Attention Hybrid: Using Ulysses inside the 8-GPU node (where all-to-all saturates 900 GB/s NVLink) and Ring Attention across nodes (where peer-to-peer rings saturate InfiniBand) to scale context to 1M+ tokens [4].
  • Asynchronous Tensor Parallelism: Research compilers (such as ByteCheckpoint and AsyncTP) that attempt to overlap tensor parallel all-reduces with independent layer GEMMs using custom CUDA graph slicing.
  • Pipeline Parallelism Interaction: How Tensor Parallelism inside nodes composes with Pipeline Parallelism across nodes in 3D parallelism for 405B-scale models (see Lesson 14, Combining Parallelism - 3D and 4D).

Summary

Mind map summarizing Tensor Parallelism, backward pass collective multipliers, Sequence Parallelism, Ring Attention, DeepSpeed-Ulysses, and architecture sizing decisions.
  • Tensor Parallelism (TP) splits weight matrices within transformer layers (ColumnParallel QKV/Gate/Up and RowParallel Out/Down). In training, backpropagation requires two additional all-reduces per layer to assemble input gradients, totaling 4 all-reduces per layer per step (128 per step for Llama 3.1 8B).
  • Sequence Parallelism (SP) shards LayerNorm, RMSNorm, and Dropout activations along the sequence dimension (s / \text{TP}). It replaces RowParallel all-reduces with reduce-scatter and all-gather, eliminating activation duplication with zero extra communication volume.
  • Context Parallelism (CP) shards the sequence across GPUs for long-context training. Ring Attention pipelines blockwise attention computation with peer-to-peer KV block circulation. DeepSpeed-Ulysses transposes sequence-sharded tensors to head-sharded tensors via all-to-all collectives.
  • Tensor Parallelism is strictly synchronous and blocking: each layer's GEMM stalls until the all-reduce concludes. On NVLink (900 GB/s), 128 all-reduces take 16.7 ms (< 0.7% overhead). Over InfiniBand (50 GB/s), network latency explodes stall time to over 300 ms (and 1.5 s for 70B). TP must stay inside a node.
  • For Llama 3.1 8B at 8,192 context on 256 H100s, TP=1 and CP=1. Hybrid Sharded Data Parallelism (HSDP) easily handles memory and activations with zero TP overhead. TP=8 is reserved for 70B+ models, and CP is activated for 32K–128K+ contexts.
