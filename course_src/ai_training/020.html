Introduction

Training a foundation model requires more than feeding an undifferentiated firehose of text into an optimization loop. A modern large language model learns world facts, algorithmic reasoning, linguistic grammar, mathematical deduction, and conversational nuance simultaneously. These distinct capabilities do not reside in a single uniform corpus; they originate in wildly disparate data domains—filtered web scrapes, source code repositories, scientific papers, digitized books, and multilingual documents [1].

The data mixture—the precise mathematical proportion allocated to each domain in the training stream—acts as the foundational genetic blueprint of the model. Allocating too little code damages the model's ability to plan and follow strict syntax, while allocating too much unstructured web text floods the parameters with low-density boilerplate. Deciding how to mix these sources, how many epochs of repetition scarce high-quality domains can tolerate, and how to schedule the data over time via a curriculum is what separates an average model from a frontier system [2].

Heterogeneous data sources—curated web, source code, math and science, multilingual corpora, and books—are assigned explicit target weights. A deterministic, resumable streaming sampler draws examples according to these proportions and packs them into 8,192-token sequences to construct the global pretraining batch of 4 million tokens per step.

In this lesson, we examine the quantitative trade-offs among pretraining domains, analyze how mixture proportions are selected using proxy models and empirical scaling laws (DoReMi and RegMix), establish the bounds on data repetition, evaluate curriculum learning and late-stage annealing, hedge the role of synthetic data, construct a complete 1-trillion-token data mixture budget for our 256-GPU cluster, and implement a deterministic, resumable weighted data loader in PyTorch.

Clarifying the Problem

In an AI infrastructure and modeling interview, data mixture and curriculum questions typically begin with a capacity or quality trade-off under a fixed token budget. Here is how a discussion between a candidate and an interviewer typically unfolds:

Candidate: What model architecture, parameter count, and token budget are we targeting for this pretraining run?
Interviewer: We are pretraining a model with the Llama 3.1 8B architecture—8.03 billion parameters across 32 layers, hidden dimension 4,096, sequence length 8,192—on a fixed budget of 1.0 trillion tokens. We are training on 256 NVIDIA H100 GPUs across 32 nodes for approximately 5.5 days.

Candidate: What raw data corpora do we have available, and what are their estimated clean volumes?
Interviewer: We have over 15 trillion tokens of filtered Common Crawl web data, about 2 trillion tokens of GitHub and open-source code, 300 billion tokens of mathematical and scientific papers, 500 billion tokens of books, and 1.5 trillion tokens of multilingual text across 20 languages.

Candidate: Are we allowed to repeat data from scarce, high-density domains such as math and code?
Interviewer: Yes, provided the repetition does not induce overfitting, memorization, or degradation in downstream general knowledge.

Candidate: What is the primary evaluation objective?
Interviewer: A balanced frontier model: strong general knowledge (MMLU), strong programming capability (HumanEval), robust multi-step reasoning (GSM8K), and solid cross-lingual comprehension, without loss spikes during training.

Candidate: Should the data mixture remain constant throughout the run, or should we alter the distribution near the end?
Interviewer: We want you to determine whether a stationary mixture or a multi-stage curriculum with annealing yields the best return on our 1T-token compute budget.

The question underneath is: How do we allocate our 1-trillion-token budget across scarce and abundant domains, determine safe repetition limits, optimize mixing weights without wasting cluster compute, and design a curriculum that maximizes reasoning without causing catastrophic forgetting? To answer it, we begin by analyzing the unique properties and trade-offs of each data source.

The Pretraining Domain Spectrum

A pretraining corpus is composed of distinct data modalities, each contributing unique inductive biases and representations to the transformer's self-attention and feed-forward layers [3]. Understanding these domains is essential before assigning mathematical mixing weights.

Comparison of the five primary pretraining domains across token volume availability, reasoning density, downstream capability transfer, and safe repetition bounds.

1. Curated Web Text

Web text extracted from dumps such as Common Crawl (e.g., FineWeb or RefinedWeb) constitutes the vast majority of raw tokens available to AI practitioners [4]. It provides the foundation for general world knowledge, facts, trivia, commonsense reasoning, and colloquial dialogue. However, raw web text is dominated by SEO spam, cookie banners, navigation links, machine-translated gibberish, and toxic commentary. Even after rigorous heuristic and perplexity filtering (Lesson 18, Deduplication and Quality Filtering), web text exhibits moderate information density. Because web tokens exist in multi-trillion quantities, models rarely need to repeat web data; it is consumed in a single epoch.

2. Source Code and Repositories

Corpora such as GitHub, BigCode's The Stack, and StarCoder contain source code across hundreds of programming languages, compiler configurations, documentation, and technical commit histories [5]. Beyond enabling programming synthesis (HumanEval, MBPP), code data provides a profound structural benefit: it forces the language model to learn strict syntax, hierarchical parsing, variable tracking, long-range dependency resolution, and algorithmic execution. Empirical research confirms that training on code improves performance on natural language reasoning tasks that contain no executable code [6]. High-quality code is moderately abundant (1 to 2 trillion clean tokens) and tolerates 2 to 3 epochs of repetition.

3. Mathematics and Scientific Literature

Comprising arXiv preprints, PubMed papers, and specialized mathematical web scrapes (such as OpenWebMath [7]), this domain contains the highest density of multi-step logical deduction, formal proofs, symbolic equations, and analytical problem-solving. It directly drives performance on benchmarks like GSM8K and MATH. However, clean mathematical tokens are extremely scarce—rarely exceeding 300 to 500 billion unique tokens globally. Furthermore, standard tokenizers often tokenize LaTeX equations inefficiently (Lesson 19, Tokenizers). Because mathematical reasoning is concept-dense rather than fact-memorizing, math corpora can tolerate 3 to 4 epochs of repetition before exhibiting deleterious memorization.

4. Books and Long-Form Prose

Digitized books (such as Project Gutenberg and literary archives) provide continuous, grammatically rich, long-form narratives spanning tens of thousands of tokens per document. Unlike fragmented web articles, books train the attention mechanism to track characters, narrative arcs, and thematic consistency across full 8,192-token contexts. The primary constraints are copyright restrictions and archaic vocabulary in public-domain sets. Books represent approximately 500 billion unique tokens and are typically sampled for 1.0 to 1.5 epochs.

5. Multilingual Corpora

Web scrapes and news feeds in non-English languages expand the model's global applicability and enable cross-lingual knowledge transfer [8]. However, mixing multilingual data introduces a subtle tokenization penalty: byte-pair encoding vocabularies trained predominantly on English allocate fewer merge tokens to non-Latin scripts (e.g., Cyrillic, Arabic, Devanagari, or East Asian characters). This higher token fertility increases the sequence length required to express a given concept, consuming more compute per sentence. Frontier models typically allocate 8% to 20% of their mixture to non-English tokens to maintain broad linguistic competence without diluting English reasoning throughput.

Choosing Mixture Weights: Heuristics to Automated Laws

Historically, pretraining mixtures were determined through trial-and-error heuristics or human intuition (such as the original Pile mixture [1]). In modern foundation model training, where a single training run costs over $100,000 on 256 H100 GPUs, empirical and automated techniques are required to find optimal mixing weights.

Two modern paradigms for data mixture selection. Left: DoReMi uses Group Distributionally Robust Optimization (Group DRO) on a 280M proxy model to dynamically upweight domains with high excess loss, transferring weights to an 8B model to achieve 2.6× faster convergence. Right: RegMix samples hundreds of random mixture proportions on 1M–10M parameter proxy models, fits a regression surface mapping mixture weights to loss, and simulates millions of mixtures to find the global optimum at 10% of DoReMi's compute cost.

Proxy-Model Ablations

The standard baseline approach trains small proxy models (e.g., 100M to 300M parameters) on a reduced token budget (e.g., 5 to 10 billion tokens) across a grid of candidate mixtures [3]. Downstream evaluations and validation perplexities are measured to identify the strongest mixture. While intuitive, brute-force grid search suffers from a combinatorial explosion: evaluating five domains at 10% granularity requires exploring dozens of mixtures, consuming tens of thousands of GPU-hours on exploratory runs.

DoReMi: Domain Reweighting with Minimax Optimization

To eliminate manual tuning, Xie et al. introduced DoReMi (Domain Reweighting with Minimax Optimization) [9]. DoReMi frames mixture selection as a game between a learner and an adversary without requiring downstream benchmark labels:

  1. Reference Model: Train a small reference model (e.g., 280M parameters) using a uniform or heuristic domain mixture \alpha_0.
  2. Proxy Model with Group DRO: Train a small proxy model of the same size using Group Distributionally Robust Optimization (Group DRO). At each step t, the proxy model measures the excess loss (regret) on domain k relative to the reference model: r_k(t) = \mathcal{L}_k(\theta_t) - \mathcal{L}_k(\theta_{\text{ref}}) The domain weights \alpha(t) are updated via exponentiated gradient ascent to prioritize domains where the proxy model lags furthest behind the reference model: \alpha_k(t+1) = \frac{\alpha_k(t) \exp(\eta r_k(t))}{\sum_{j=1}^K \alpha_j(t) \exp(\eta r_j(t))} where \eta is the step size.
  3. Transfer to Full Scale: Average the domain weights produced over the proxy run and use them to train the full-scale model (e.g., 8B parameters).

Xie et al. demonstrated that domain weights derived from a 280M proxy model transferred directly to an 8B model (a 30× scale factor), reaching the baseline model's downstream benchmark accuracy 2.6× faster on The Pile [9].

RegMix and Data Mixing Laws

While DoReMi optimizes worst-case domain regret, it does not directly predict downstream benchmark performance. Liu et al. introduced RegMix (Data Mixture as Regression for Language Model Pre-training) [10], which treats data mixture selection as an empirical regression problem:

  1. Dirichlet Sampling: Sample 256 to 512 diverse mixture weight vectors \vec{\alpha} = (\alpha_1, \alpha_2, \dots, \alpha_K) from a Dirichlet distribution.
  2. Massive Micro-Proxy Training: Train hundreds of ultra-small proxy models (e.g., 1M to 10M parameters) on a small token slice (e.g., 1 billion tokens each). Because these models are tiny, training 512 models consumes less than 10% of the compute required for a single 1B-parameter ablation run.
  3. Regression Fitting: Fit a regression model (e.g., Ridge regression, Random Forest, or Neural Network) mapping mixture proportions \vec{\alpha} to validation loss or downstream task accuracy: \hat{\mathcal{L}}(\vec{\alpha}) = \sum_{k=1}^K w_k \alpha_k + \sum_{i \le j} w_{ij} \alpha_i \alpha_j + b where interaction terms \alpha_i \alpha_j capture non-linear synergies between domains.
  4. Simulation and Optimization: Evaluate millions of synthetic mixture vectors through the fitted regression model in seconds, finding the Pareto-optimal mixture vector \vec{\alpha}^* that minimizes target loss.

Concurrently, Ye et al. established formal Data Mixing Laws [11], proving that multi-domain loss follows a predictable scaling surface governed by parameter capacity and domain transferability. Their findings revealed that code and web text exhibit strong positive transfer, whereas high-capacity models require higher code and math ratios than smaller models to fully saturate their representational capacity.

Repetition, Epochs, and Data-Constrained Scaling

In classical machine learning, training for multiple epochs over a fixed dataset is standard practice. In modern large language model pretraining, Chinchilla scaling laws (Hoffmann et al., 2022 [12]; see Lesson 8, Scaling Laws) historically assumed that models should be trained on uniquely sampled tokens in a single epoch (D_{\text{unique}} = D_{\text{train}}). However, as pretraining budgets expand toward tens of trillions of tokens, high-quality human text is being exhausted.

To quantify the exact degradation incurred when repeating data, Muennighoff et al. conducted extensive empirical studies in Scaling Data-Constrained Language Models [13]. Their findings establish three clear operational regimes:

Empirical validation loss trajectories across repetition regimes. Unique data yields optimal scaling. Repeating data for up to 2 epochs causes no perceptible loss degradation. Up to 4 epochs incurs negligible loss (< 0.1%), making repetition highly effective for scarce domains. Beyond 4 epochs, severe memorization causes validation loss to plateau or diverge.
  • 1.0 to 2.0 Epochs: Training for up to two full passes over high-quality data yields performance indistinguishable from training on entirely unique tokens. The parameter updates continue to extract generalized linguistic and factual patterns without memorization.
  • 2.0 to 4.0 Epochs: Between two and four passes, models experience minor diminishing returns. The validation loss gap between repeated data and unique data remains below 0.1%, which is negligible compared to the massive reasoning gains achieved by including dense mathematical or code corpora.
  • Beyond 4.0 Epochs: When repetition exceeds 4 to 5 passes, the rate of learning decays sharply. The model begins memorizing specific sequences, training loss continues to drop while validation loss on held-out text plateaus or diverges, and downstream generalization collapses.

This empirical rule dictates our mixture design: abundant domains (curated web and multilingual) must receive exactly 1.0 epoch (zero repetition), whereas scarce, high-density domains (code, mathematics, and academic science) can be safely repeated for 2.0 to 3.0 epochs to hit target token allocations.

Curriculum Learning, Annealing, and Context Extension

Curriculum Learning: Mixed Evidence

Curriculum learning, introduced by Bengio et al. [14], hypothesizes that neural networks learn faster and achieve better generalization when trained on easy examples first before advancing to complex concepts. In the context of LLMs, researchers have tested curricula based on sentence length, vocabulary complexity, reading level, and domain sequencing (e.g., training purely on Wikipedia and books before introducing raw web scrapes).

However, extensive empirical investigations across foundation model pretraining have yielded mixed evidence [15]. Rigid early-stage curricula often induce catastrophic forgetting: a model trained exclusively on simple prose in early phases rapidly forgets those distributions when abruptly transitioned to technical code and mathematics. In practice, maintaining a stationary, uniform mixture across the vast majority of pretraining (90% to 95% of total tokens) proves remarkably robust, preventing domain drift while allowing all attention heads to develop balanced representations.

Late-Stage Annealing (Mid-Training)

While an early-stage curriculum provides questionable value, a late-stage curriculum—known as annealing or mid-training—has emerged as one of the most powerful techniques in frontier model engineering [2] [16].

The three-stage pretraining curriculum for Llama 3.1 8B. Stage 1 executes 95% of the run on an 8,192-token context with a stationary mixture and cosine learning rate decay. Stage 2 extends the context window to 32k/128k using RoPE scaling over 10B tokens. Stage 3 executes an annealing phase over the final 40B tokens, linearly decaying learning rate to zero while upsampling high-quality code and math to 80% of the stream.

In The Llama 3 Herd of Models [2], Meta detailed how annealing dramatically boosts downstream benchmark performance. During standard pretraining, the learning rate follows a cosine decay schedule. In the final phase of pretraining (covering the final 40 million to 40 billion tokens), two critical adjustments are applied simultaneously:

  1. Data Distribution Shift: The pretraining mixture is dynamically altered to heavily upsample high-quality mathematical reasoning, algorithmic code, and curated instructional datasets, pushing their combined weight from ~32% to over 70%–80% of the active token stream.
  2. Linear Learning Rate Decay to Zero: The learning rate is annealed linearly from its current value down to exactly zero.
  3. Model Checkpoint Averaging: Multiple checkpoints saved across the annealing window are combined using uniform Polyak averaging to produce the final pre-trained weights.

Meta reported that this late-stage annealing phase yielded dramatic gains on reasoning benchmarks for the Llama 3 8B model: validation accuracy on GSM8K surged by 24.0%, and performance on MATH improved by 6.4%, all without degrading general knowledge or reading comprehension [2]. Annealing acts as a low-cost alignment bridge between broad pretraining and post-training fine-tuning.

Phased Long-Context Extension

Modern foundation models support context windows of 32,768 to 131,072 tokens. However, training an 8B model from token 0 on 128k sequences is computationally prohibitive because self-attention memory and compute scale quadratically without specialized context parallelism (Lesson 12, Tensor, Sequence and Context Parallelism).

The standard industry solution is a phased context curriculum [2]:

  • Phase 1 (Base Pretraining): Train for 95% of the total budget (e.g., 950 billion tokens) at a standard context length of 8,192 tokens. This captures foundational language modeling and knowledge representations at maximum hardware MFU.
  • Phase 2 (Context Extension): Increase the context window incrementally (e.g., 8k \to 32k \to 128k) over a small token slice (e.g., 10 to 50 billion tokens). During this phase, the Rotary Position Embedding (RoPE) base frequency \theta is scaled upward (e.g., from 10,000 to 500,000) to adjust frequency wavelengths for long sequences.
  • Phase 3 (Annealing): Execute the final high-quality annealing phase at the target long-context window.

Synthetic Data in Pretraining

With high-quality human text approaching exhaustion, synthetic data generated by frontier models (such as GPT-4 or Claude 3.5 Sonnet) has gained significant traction. Pioneer studies such as Microsoft's Textbooks Are All You Need (Phi-1 and Phi-2 [17]) and Hugging Face's Cosmopedia [18] showed that training smaller models on synthetic textbooks, coding exercises, and synthetic web syntheses can achieve remarkably high benchmark scores with relatively few tokens.

However, claims regarding synthetic pretraining data must be heavily hedged in production environments:

  • Evaluation Benchmark Contamination: When frontier models are prompted to generate synthetic "reasoning exercises", their outputs often mirror the exact stylistic patterns and problem templates found in public evaluation sets (GSM8K, HumanEval, ARC). High benchmark scores can reflect latent memorization rather than generalized reasoning.
  • Diversity and Tail Collapse: Synthetic data generators reflect the mode of their own training distributions. They lack the chaotic, idiosyncratic edge cases, obscure cultural references, and typographical anomalies present in real-world human writing. Training exclusively or excessively on synthetic data leads to model collapse and severe hallucinations on out-of-distribution prompts [19].
  • Stylistic Homogenization: Synthetic corpora frequently repeat distinct conversational boilerplate ("Certainly! Here is an explanation...", "In conclusion, it is important to remember..."), which degrades the base model's stylistic versatility.
Treat synthetic data as a targeted spice rather than the main meal. Allocate between 5% and 15% of your pretraining budget to synthetic data, focusing strictly on domains where human data is deficient (e.g., step-by-step mathematical solutions and unit-tested code explanation). Always execute MinHash deduplication between synthetic training prompts and evaluation test sets.

The Annealing Sub-Mixture

For the final 40 billion tokens of the run (from token 960B to 1,000B), the data loader dynamically shifts mixture weights to the annealing distribution: 40% Mathematics, 40% Source Code, and 20% Curated Web. Concurrently, the optimizer learning rate linearly decays from 3 \times 10^{-5} down to zero.

Which mixture strategy fits our run?

For our 256-GPU cluster pretraining Llama 3.1 8B, we select a two-stage hybrid strategy: RegMix optimization on micro-proxies followed by late-stage annealing. We run RegMix across 256 micro-models (10M parameters each) consuming less than 1,000 GPU-hours (< 3% of our 33,800 GPU-hour budget) to tune exact code and math interaction coefficients. We execute the main pretraining phase (0 to 960B tokens) using this stationary mixture at 8,192 sequence length. In the final 40B tokens, we transition to our high-quality annealing mix with linear learning rate decay. This maximizes compute efficiency, avoids early curriculum instability, and delivers peak reasoning performance on GSM8K and HumanEval.

It samples tokens according to target domain weights, handles infinite cycling for repeated sources, and maintains resumable state pointers so that training can be paused and restarted without skipping or duplicating data. import json import random from typing import Dict, Iterator, List, Any import numpy as np class ResumableWeightedDataSampler: """ Deterministic, resumable multi-source weighted data loader. Samples tokens across heterogeneous domains according to target probabilities. Supports state_dict and load_state_dict for seamless checkpoint resumption. """ def __init__( self, domain_files: Dict[str, List[str]], target_weights: Dict[str, float], seed: int = 42, tokens_per_sample: int = 8192 ): self.domain_names = sorted(target_weights.keys()) total_w = sum(target_weights[d] for d in self.domain_names) self.probabilities = np.array([target_weights[d] / total_w for d in self.domain_names], dtype=np.float64) self.seed = seed self.rng = np.random.default_rng(seed) self.tokens_per_sample = tokens_per_sample # State tracking per domain: shard index and document offset self.domain_shards = domain_files self.state = { d: {"shard_idx": 0, "doc_offset": 0, "epoch": 0} for d in self.domain_names } self.total_tokens_yielded = 0 def state_dict(self) -> Dict[str, Any]: """Serialize sampler state for checkpointing.""" return { "state": {d: dict(v) for d, v in self.state.items()}, "total_tokens_yielded": self.total_tokens_yielded, "rng_state": self.rng.bit_generator.state } def load_state_dict(self, checkpoint: Dict[str, Any]) -> None: """Restore exact sampler state from checkpoint.""" self.state = {d: dict(v) for d, v in checkpoint["state"].items()} self.total_tokens_yielded = checkpoint["total_tokens_yielded"] self.rng.bit_generator.state = checkpoint["rng_state"] def sample_batch(self, batch_size: int = 8) -> List[Dict[str, Any]]: """Sample a batch of sequences matching target domain distribution.""" selected_indices = self.rng.choice(len(self.domain_names), size=batch_size, p=self.probabilities) batch = [] for idx in selected_indices: domain = self.domain_names[idx] # Advance domain offset; Dynamically shifts sampling weights and decays learning rate during final tokens. """ def __init__( self, base_weights: Dict[str, float], anneal_weights: Dict[str, float], total_tokens: int = 1_000_000_000_000, anneal_tokens: int = 40_000_000_000, base_lr: float = 3e-4, min_lr: float = 3e-5 ): self.base_weights = base_weights self.anneal_weights = anneal_weights self.total_tokens = total_tokens self.anneal_start_token = total_tokens - anneal_tokens self.base_lr = base_lr self.min_lr = min_lr def get_config_at_token(self, current_token: int) -> Dict[str, Any]: """Returns active domain weights and learning rate for current progress.""" if current_token < self.anneal_start_token: # Stage 1 & 2: Cosine decay over main pretraining phase progress = current_token / self.anneal_start_token cosine_mult = 0.5 * (1.0 + math.cos(math.pi * progress)) lr = self.min_lr + (self.base_lr - self.min_lr) * cosine_mult return {"weights": self.base_weights, "lr": lr, "phase": "base_pretraining"} else: # Stage 3: Annealing phase - Linear decay of LR to zero, upweighted mix anneal_progress = (current_token - self.anneal_start_token) / (self.total_tokens - self.anneal_start_token) anneal_progress = min(max(anneal_progress, 0.0), 1.0) # Interpolate domain weights toward annealing distribution active_weights = {} for d in self.base_weights: w_start = self.base_weights.get(d, 0.0) w_end = self.anneal_weights.get(d, 0.0) active_weights[d] = w_start + (w_end - w_start) * anneal_progress # Linear decay from current LR down to zero current_base_lr = self.min_lr lr = current_base_lr * (1.0 - anneal_progress) return {"weights": active_weights, "lr": lr, "phase": "annealing"} # Example progress checkpoints controller = AnnealingCurriculumController( base_weights={"web": 0.55, "code": 0.20, "math": 0.12, "books": 0.05, "multi": 0.08}, anneal_weights={"web": 0.20, "code": 0.40, "math": 0.40, "books": 0.00, "multi": 0.00} ) print("At 500B tokens:", controller.get_config_at_token(500_000_000_000)) print("At 980B tokens:", controller.get_config_at_token(980_000_000_000))

Other Talking Points

If there is extra time at the end of the interview, here are some additional talking points:

  • Loss Spikes from Malformed Data Shards: Sudden loss spikes during pretraining are frequently caused by bad data batches (e.g., a burst of repetitive spam, HTML table garbage, or extreme gradient norms from unexpected token sequences) rather than hardware faults. Isolating and skipping corrupted shards is covered in Lesson 32, Training Stability - Loss Spikes and Divergence.
  • Domain-Specific Learning Rates: While standard practice uses a single global optimizer learning rate, research in multi-task learning has explored per-domain learning rates or gradient clipping thresholds to prevent unstable updates on noisy web data.
  • Dynamic Batch Balancing across Data-Parallel Ranks: When sampling heterogeneous data streams across 256 GPUs, if one domain produces shorter documents that pack poorly, individual ranks may idle. Modern distributed loaders balance token volume across all DP ranks using coordinated distributed samplers.
  • Tokenizer Fertility Disparities: A tokenizer trained primarily on English requires 2× to 4× more tokens to represent Asian or Cyrillic languages. When allocating multilingual mixture weights, calculate weights by information content or byte volume rather than raw token count to avoid under-representing non-English semantics.
  • Polyak Checkpoint Averaging: Averaging model weights across the final 5 to 10 checkpoints saved during late-stage annealing acts as a stochastic weight averaging (SWA) regularizer, smoothing out loss landscape local minima and improving out-of-distribution evaluation scores.
  • Benchmark Contamination Auditing: Prior to freezing the pretraining mixture, run 8-gram or 13-gram exact match filtering against common evaluation benchmarks (GSM8K, MMLU, HumanEval) to prevent artificial benchmark inflation (Lesson 35, Benchmarks and Contamination).

Summary

  • Pretraining mixtures combine diverse sources (curated web, source code, mathematics, multilingual, and books) to impart world knowledge, algorithmic logic, deduction, and fluency simultaneously.
  • Automated methods replace expensive manual tuning: DoReMi optimizes worst-case domain regret via Group DRO on a proxy model (2.6× faster convergence), while RegMix fits regression surfaces across micro-proxies at < 3% compute overhead.
  • Data repetition scaling shows that scarce high-density domains (math, code) can be repeated for up to 4 epochs with negligible degradation (< 0.1% loss), while abundant web text is consumed in a single epoch.
  • Early-stage curricula show mixed results and risk catastrophic forgetting; late-stage annealing (linearly decaying learning rate to zero while upsampling code and math) provides massive reasoning boosts (+24% on GSM8K in Llama 3).
  • For our 1T-token Llama 3.1 8B run on 256 H100 GPUs, we allocate 55% Web (1 ep), 20% Code (2 ep), 12% Math (3 ep), 8% Multilingual (1 ep), and 5% Books (1 ep), requiring 820 billion unique tokens.
