Forward and Backward Passes

Introduction

Every step of neural network training boils down to an orchestration of four sequential phases: evaluating a candidate prediction through a forward pass, measuring prediction discrepancy via a loss function, calculating exact parameter gradients by reversing the computation through backpropagation, and adjusting weights using an optimization rule [1]. While inference executes only the forward pass and discards intermediate results as soon as each layer finishes, training is bound by the mathematical demands of the backward pass. Backpropagation requires access to the intermediate activations generated during the forward pass to compute parameter gradients, forcing the system to store gigabytes of transient state across every layer of the model [2].

Furthermore, training exhibits a fundamental computational asymmetry: the backward pass costs roughly twice the floating-point operations (FLOPs) of the forward pass. For a standard linear projection, the forward pass performs a single matrix multiplication to project input activations into output representations. The backward pass, however, must perform two distinct matrix multiplications: one to backpropagate the error gradient to preceding layers, and a second to compute the gradient with respect to the layer weights [3]. This reality establishes the canonical 6ND rule of language model pretraining—each token requires approximately 6N FLOPs per step (2ND forward and 4ND backward for N parameters and D tokens), rising to 8ND when activations are recomputed to save GPU memory [4].

In this lesson, we examine the mathematical foundations and systems engineering of the forward and backward passes. We walk through a hand-calculated numeric backpropagation example on a two-layer network, analyze how next-token cross-entropy loss behaves across high-dimensional vocabularies, prove why the backward pass requires twice the compute of the forward pass, and dissect PyTorch autograd mechanics and gradient accumulation during large-scale pretraining.

The question underneath is: How do we map the mathematical chain rule onto modern GPU hardware, budget the computational FLOPs and transient memory buffers for an 8B model, and coordinate micro-batch execution to maintain 40% hardware efficiency? To answer it, we begin with the core mechanics of backpropagation.

The Mechanics of Backpropagation

The computation graph

Modern deep learning frameworks represent mathematical expressions as a directed acyclic graph (DAG) known as a computation graph [2]. In this graph, leaf nodes represent input data tensors or learnable model parameters (weights and biases). Internal nodes represent mathematical operations, such as matrix multiplications, bias additions, layer normalizations, or non-linear activation functions. Directed edges represent the flow of multi-dimensional arrays (tensors) between operations.

During the forward pass, the framework traverses the graph in topological order, executing GPU kernels to compute intermediate tensors until it evaluates the scalar loss ℒ. When an operation executes, PyTorch records an internal backward node (a subclass of torch.autograd.Function) containing the recipe for computing vector-Jacobian products for that operation. During the backward pass, the framework traverses this graph in exact reverse topological order, seeding the root with ∂ℒ∂ℒ=1.0 and propagating gradients backward toward the parameters.

The chain rule in reverse

Consider a composite function where an input x undergoes a sequence of transformations z1=f(x), z2=g(z1), producing output y=h(z2) evaluated by scalar loss ℒ(y). According to the multivariable chain rule of calculus, the sensitivity of the loss with respect to the input is the product of intermediate Jacobians:

∂ℒ∂x=∂ℒ∂y∂y∂z2∂z2∂z1∂z1∂x

In forward-mode automatic differentiation, derivatives are evaluated from left to right (from inputs toward outputs). For a neural network with N parameters and a single scalar loss ℒ:ℝN→ℝ, forward-mode differentiation would require N separate forward sweeps through the graph, scaling proportionally to parameter count. In reverse-mode automatic differentiation (backpropagation), derivatives are evaluated from right to left (from the scalar loss back toward the parameters). Because the output is a single scalar (ℝ1), a single reverse sweep computes the exact gradient with respect to all N parameters simultaneously [1].

Worked numeric example: a two-layer network by hand

To demystify backpropagation, let us trace a complete numeric forward and backward pass on a concrete, two-layer bias-free network small enough to verify with paper and pencil. Let the input vector be x∈ℝ2, the first weight matrix be W1∈ℝ2×2, the activation function be a rectified linear unit (ReLU), the second weight vector be W2∈ℝ1×2, and the target scalar be y:

x=[2.01.0],W1=[1.00.5−0.52.0],W2=[0.8−1.2],y=1.8

1. Forward pass evaluation

First, compute the linear projection of Layer 1:

z1=W1x=[1.0(2.0)+0.5(1.0)−0.5(2.0)+2.0(1.0)]=[2.0+0.5−1.0+2.0]=[2.51.0]

Next, apply the elementwise ReLU activation function a1=max(0,z1). Because both components of z1 are positive:

a1=ReLU([2.51.0])=[2.51.0]

Next, compute the linear projection of Layer 2 to produce prediction y^:

y^=W2a1=[0.8−1.2][2.51.0]=0.8(2.5)+(−1.2)(1.0)=2.0−1.2=0.8

Finally, evaluate the mean squared error loss ℒ=12(y^−y)2:

ℒ=12(0.8−1.8)2=12(−1.0)2=0.50

2. Backward pass backpropagation

Now we execute the chain rule in reverse, starting from the loss:

Step 1: Output error gradient. Differentiate the loss with respect to prediction y^:

δy=∂ℒ∂y^=y^−y=0.8−1.8=−1.0

Step 2: Gradients at Layer 2. Differentiate with respect to weight vector W2 and hidden activation a1:

∂ℒ∂W2=δya1⊤=−1.0[2.51.0]=[−2.5−1.0] ∂ℒ∂a1=W2⊤δy=[0.8−1.2](−1.0)=[−0.81.2]

Notice the critical systems insight: computing ∂ℒ∂W2 requires the forward activation a1. If the GPU had freed a1 after the forward pass, it could not calculate the weight gradient.

Step 3: Gradients through ReLU. The derivative of ReLU is the unit step function 1(z1>0). Multiplying elementwise:

δ1=∂ℒ∂z1=∂ℒ∂a1⊙1(z1>0)=[−0.81.2]⊙[11]=[−0.81.2]

Step 4: Gradients at Layer 1. Differentiate with respect to weight matrix W1 and input vector x:

∂ℒ∂W1=δ1x⊤=[−0.81.2][2.01.0]=[(−0.8)(2.0)(−0.8)(1.0)(1.2)(2.0)(1.2)(1.0)]=[−1.6−0.82.41.2] ∂ℒ∂x=W1⊤δ1=[1.0−0.50.52.0][−0.81.2]=[1.0(−0.8)+(−0.5)(1.2)0.5(−0.8)+2.0(1.2)]=[−0.8−0.6−0.4+2.4]=[−1.42.0]

Every number aligns with machine precision. The outer product δ1x⊤ demonstrates why computing the parameter gradient ∂ℒ∂W1 strictly depends on retaining the input tensor x in memory.

Next-Token Prediction and Cross-Entropy Loss

The language modeling objective

Modern autoregressive large language models are trained using self-supervised next-token prediction. Given an input sequence of discrete token indices (x1,x2,…,xT), the joint probability distribution decomposes via the probability chain rule:

P(x1:T)=∏t=1TP(xt∣x<t)

At each sequence position t, the transformer backbone outputs a normalized continuous representation ht∈ℝdmodel. The language model head projects this vector across the entire vocabulary of size V using embedding weight matrix Wvocab∈ℝV×dmodel to produce raw unnormalized logits zt∈ℝV:

zt=Wvocabht

The softmax function converts these logits into a valid categorical probability distribution over the vocabulary:

pt,i=exp(zt,i)∑j=1Vexp(zt,j)

Given ground-truth target token index yt∈{1,…,V}, the training objective minimizes the cross-entropy loss, which corresponds to the negative log-likelihood of the correct token:

ℒt=−logpt,yt=−zt,yt+log(∑j=1Vexp(zt,j))

The gradient w.r.t. logits: p−y

To backpropagate through the loss, we calculate the partial derivative of ℒt with respect to any arbitrary logit zt,i. Using calculus on the expanded log-sum-exp expression:

∂ℒt∂zt,i=−∂zt,yt∂zt,i+1∑j=1Vexp(zt,j)∂∂zt,i(∑j=1Vexp(zt,j))

The first term equals −1 if i=yt and 0 otherwise, written compactly using the indicator function −1(i=yt). In the second term, only the j=i term has a non-zero derivative, yielding exp(zt,i):

∂ℒt∂zt,i=−1(i=yt)+exp(zt,i)∑j=1Vexp(zt,j)=pt,i−1(i=yt)

In vector notation, where yt is represented as a one-hot vector with 1 at the target index, this gradient simplifies to:

∇ztℒt=pt−yt

This result provides deep intuition: the error signal feeding into the backward pass is simply the difference between the model's predicted probability distribution and the true ground-truth distribution. For every incorrect token (i≠yt), the gradient is positive (+pt,i), pushing its logit downward during gradient descent. For the target token (i=yt), the gradient is negative (pt,yt−1<0), driving its logit upward.

The memory bottleneck of large vocabularies

While the mathematical form p−y is simple, its physical materialization on GPUs represents a notorious memory bottleneck. In Llama 3.1 8B, the vocabulary size is V=128,256. For a micro-batch of b=1 with sequence length s=8,192, the logits tensor z contains:

1×8,192×128,256=1,050,673,152 elements

Because softmax and cross-entropy require full 32-bit floating-point precision to prevent numerical overflow in the exponent sum, storing this unchunked logit tensor requires 1.05×109×4 bytes≈4.20 GB of memory for a single sequence. Storing the corresponding probability tensor and backward gradient adds another 8.4 GB, consuming over 12 GB of GPU High Bandwidth Memory (HBM) purely for the loss calculation.

To eliminate this waste, modern pretraining stacks employ chunked cross-entropy (or fused loss kernels such as Liger-Kernel or FlashCrossEntropy). Instead of materializing the entire [b,s,V] logit tensor in HBM, the sequence dimension is divided into smaller chunks (for example, 512 tokens). For each chunk, the GPU projects hidden states to logits, computes the softmax reduction, evaluates the loss, immediately calculates the backward gradient p−y, backpropagates into the hidden state gradient ∇hℒ, and discards the logit chunk. This reduces peak loss memory from 4.2 GB down to less than 270 MB without altering mathematical results.

Why the Backward Pass Costs Twice the Forward Pass (6ND Rule)

The anatomy of a linear layer

The core computational primitive in transformers is the general matrix multiplication (GEMM). Consider a standard feed-forward or projection layer with weight matrix W∈ℝDin×Dout operating on an input activation tensor X∈ℝB×Din, where B=b×s represents the total batch tokens:

Y=XW

Computing each scalar element of Y requires an inner product between a row of X (length Din) and a column of W (length Din), which entails Din multiplications and Din\)additions—totaling<tex>2Din floating-point operations. Because Y has B×Dout elements, the forward pass compute is:

FLOPsforward=2BDinDout=2×(tokens)×(parameters)

During the backward pass, backpropagation receives the upstream loss gradient G=∂ℒ∂Y∈ℝB×Dout. To complete the step, the layer must calculate two separate tensor derivatives:

  1. Gradient with respect to input activations (∂ℒ∂X): To propagate error signals backward to earlier layers, the framework multiplies incoming gradients by the transposed weight matrix: ∂ℒ∂X=GW⊤where G∈ℝB×Dout,W⊤∈ℝDout×Din This GEMM produces a [B×Din] tensor. Its computational cost is 2BDoutDin FLOPs.
  2. Gradient with respect to layer weights (∂ℒ∂W): To update the model's parameters, the framework multiplies the transposed input activations by the incoming gradients: ∂ℒ∂W=X⊤Gwhere X⊤∈ℝDin×B,G∈ℝB×Dout This GEMM produces a [Din×Dout] parameter gradient tensor. Its computational cost is 2DinBDout FLOPs.

Summing the two backward operations yields:

FLOPsbackward=2BDoutDin+2DinBDout=4BDinDout=2×FLOPsforward

Because the backward pass must evaluate two full matrix multiplications for every forward matrix multiplication, the backward pass requires exactly twice the compute of the forward pass. Combining the forward and backward passes gives the fundamental 6ND scaling rule formulated by Kaplan et al. [3] and Hoffmann et al. [4]:

Total FLOPs per Step=2ND+4ND=6ND

where N is the non-embedding parameter count and D is the number of tokens processed in the batch (explored thoroughly in Lesson 7, Training FLOPs, Time and MFU).

Full activation recomputation (8ND)

In standard training, intermediate activations X are retained in GPU memory from the forward pass until their corresponding backward GEMM executes. However, as derived in Lesson 3 (Training Memory), for long sequences (such as 8,192 tokens), storing activations across all 32 layers requires hundreds of gigabytes of HBM, creating an immediate Out-Of-Memory (OOM) crash [5].

To eliminate this activation memory, systems use activation checkpointing (also called gradient checkpointing). Instead of saving all intermediate tensors, the forward pass saves only the inputs at the boundaries of each transformer layer (or block). During the backward pass, when backpropagation reaches a layer, it re-executes the forward pass for that layer from its cached input, regenerating the intermediate activations immediately before computing ∂ℒ∂W and ∂ℒ∂X [5].

Re-executing the forward pass adds an extra 2ND FLOPs of compute to the training step:

FLOPs with Checkpointing=2ND (forward)+2ND (recompute)+4ND (backward)=8ND

Activation recomputation incurs a 33.3% computational overhead (8ND/6ND=1.333). In exchange, it slashes activation memory by over 90%, making it possible to train modern 8K-context models on standard hardware.

Which activation retention strategy fits our run?

For pretraining Llama 3.1 8B with sequence length 8,192 on our 256 H100 cluster, uncheckpointed activation storage requires approximately 380 GB per GPU—exceeding device memory by nearly 5×. Conversely, full activation checkpointing adds 33% compute overhead (8ND). The optimal strategy is selective activation checkpointing combined with FlashAttention-3 [6]. FlashAttention never writes the s×s attention score matrix to HBM, eliminating the quadratic memory term entirely. We checkpoint only the large MLP feed-forward blocks while retaining attention linear projections. This reduces activation memory to under 28 GB per GPU, fitting comfortably within the 80 GB budget while avoiding the full 33% FLOP penalty.

Autograd and Gradient Accumulation in PyTorch

How PyTorch Autograd works

PyTorch features an tape-based automatic differentiation engine called autograd [2]. When a tensor with requires_grad=True participates in an operation, autograd dynamically allocates a node in the computation graph. Each tensor exposes a .grad_fn attribute referencing the backward operation that created it.

When the user invokes loss.backward(), autograd performs the following steps:

  1. Executes a topological sort starting from the loss tensor's .grad_fn to establish backward evaluation order.
  2. Iteratively executes each node's vector-Jacobian product kernel, streaming intermediate gradients to predecessor nodes.

    import torch
import torch.nn as nn

# 1. Inspecting the dynamic computation graph
x = torch.tensor([2.0, 1.0], requires_grad=True)
W1 = torch.tensor([[1.0, 0.5], [-0.5, 2.0]], requires_grad=True)
W2 = torch.tensor([0.8, -1.2], requires_grad=True)
y_target = torch.tensor(1.8)

# Forward pass
z1 = W1 @ x
a1 = torch.relu(z1)
y_hat = W2 @ a1
loss = 0.5 * (y_hat - y_target) ** 2

print("Loss value:", loss.item())                 # 0.50
print("Loss grad_fn:", loss.grad_fn)             # <MulBackward0>
print("y_hat grad_fn:", y_hat.grad_fn)           # <DotBackward0>
print("a1 grad_fn:", a1.grad_fn)                 # <ReluBackward0>

# Backward pass
loss.backward()

# Verify exact hand-calculated gradients from text
print("\n--- Verified Gradients ---")
print("dL/dW2:", W2.grad.tolist())               # [-2.5, -1.0]
print("dL/dW1:\n", W1.grad.tolist())             # [[-1.6, -0.8], [2.4, 1.2]]
print("dL/dx:", x.grad.tolist())                 # [-1.4, 2.0]

# 2. Demonstrating in-place gradient accumulation
loss2 = 0.5 * (W2 @ torch.relu(W1 @ x) - y_target) ** 2
loss2.backward()
print("\nAccumulated dL/dW2 without zero_grad:", W2.grad.tolist())  # [-5.0, -2.0]

# 3. Demonstrating set_to_none=True
optimizer = torch.optim.SGD([W1, W2], lr=0.01)
optimizer.zero_grad(set_to_none=True)
print("W2.grad after zero_grad(set_to_none=True):", W2.grad)         # None
    import torch
import torch.nn as nn
import torch.nn.functional as F

class TinyTransformer(nn.Module):
    """Minimal causal transformer block for pretraining demonstration."""
    def __init__(self, vocab_size: int = 1024, d_model: int = 128, n_heads: int = 4):
        super().__init__()
        self.tok_emb = nn.Embedding(vocab_size, d_model)
        self.head = nn.Linear(d_model, vocab_size, bias=False)
        self.attn = nn.MultiheadAttention(d_model, n_heads, batch_first=True)
        self.norm = nn.LayerNorm(d_model)

    def forward(self, idx: torch.Tensor) -> torch.Tensor:
        b, s = idx.shape
        x = self.tok_emb(idx)
        mask = nn.Transformer.generate_square_subsequent_mask(s, device=idx.device)
        attn_out, _ = self.attn(x, x, x, attn_mask=mask, is_causal=True)
        h = self.norm(x + attn_out)
        logits = self.head(h)  # shape: [b, s, vocab_size]
        return logits

# Setup execution
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
model = TinyTransformer().to(device)
optimizer = torch.optim.AdamW(model.parameters(), lr=3e-4, weight_decay=0.1)

# Synthetic batch: global batch 4 sequences split into micro-batches of 1
vocab_size = 1024
seq_len = 64
accumulation_steps = 4
data = torch.randint(0, vocab_size, (accumulation_steps, seq_len + 1), device=device)

model.train()
optimizer.zero_grad(set_to_none=True)

# Training step with gradient accumulation
for micro_step in range(accumulation_steps):
    # Slice inputs and shifted targets for next-token prediction
    inputs = data[micro_step, :-1].unsqueeze(0)   # [1, seq_len]
    targets = data[micro_step, 1:].unsqueeze(0)   # [1, seq_len]

    # 1. Forward pass
    logits = model(inputs)

    # 2. Loss computation (scaled by 1 / accumulation_steps)
    loss = F.cross_entropy(logits.view(-1, vocab_size), targets.view(-1))
    scaled_loss = loss / accumulation_steps

    # 3. Backward pass (accumulates into .grad)
    scaled_loss.backward()
    print(f"  Micro-batch {micro_step + 1}/{accumulation_steps} loss: {loss.item():.4f}")

# 4. Optimizer step
# Clip gradient norm to prevent exploding gradients
grad_norm = nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
optimizer.step()
optimizer.zero_grad(set_to_none=True)
print(f"Global step complete. Clipped gradient norm: {grad_norm:.4f}")

    Other Talking Points

    If there is extra time at the end of the interview, here are some additional talking points:

    • Loss scaling in mixed precision: When executing backward passes in FP16, small gradient values underflow to zero. While BF16 has an 8-bit exponent matching FP32 and avoids scaling, FP16 requires dynamic loss scaling to shift gradients into representable range (detailed in Lesson 5, Mixed Precision Training - BF16 and FP8).
    • Gradient checkpointing re-entrant vs non-reentrant: Early PyTorch implementations used re-entrant autograd checkpointing, which had issues with hooks and early tensor deallocation. Modern PyTorch uses torch.utils.checkpoint.checkpoint(use_reentrant=False), which integrates natively with autograd graph execution.
    • Fused cross-entropy and loss-head kernels: Chunking the cross-entropy projection across vocabulary dimensions avoids ever writing full [b,s,V] logit tensors to HBM, saving up to 4 GB of activation memory per stream in Llama 3 models.
    • Double backward and gradient penalties: Certain regularization methods (such as gradient penalty in WGANs or Hessian-vector products) require differentiating through the backward graph itself, requiring create_graph=True during the first backward call.
    • Overlap of backward compute and collective communication: In Distributed Data Parallel (DDP), gradient all-reduce communication overlaps asynchronously with the backward pass of earlier layers via backward hooks, hiding inter-node communication latency (Lesson 10, Data Parallelism and All-Reduce).
    • Memory profiling with PyTorch profiler: Using torch.profiler.profile(with_stack=True, profile_memory=True) lets engineers inspect exact allocation and deallocation events for intermediate activations throughout the forward-backward cycle.

    Summary

    • A single training step consists of four sequential phases: forward activation evaluation (2ND FLOPs), loss evaluation against vocabulary targets, backward backpropagation (4ND FLOPs), and master weight optimization.
    • The backward pass costs twice the forward pass because each linear layer requires two matrix multiplications: one to propagate gradients to inputs (GW⊤), and one to calculate parameter updates (X⊤G).
    • Standard training requires approximately 6ND FLOPs per token, which increases to 8ND when full activation checkpointing re-evaluates the forward pass during backpropagation.
    • Backpropagation through next-token cross-entropy yields the gradient p−y, pushing probability mass directly toward the target token. Large vocabularies (128,256) require chunked cross-entropy to avoid gigabytes of transient logit allocations.
    • PyTorch autograd dynamically constructs an evaluation graph and accumulates gradients into .grad buffers via in-place addition, requiring optimizer.zero_grad(set_to_none=True) between global steps.
    • On 256 NVIDIA H100 GPUs, pretraining Llama 3.1 8B with a 4M-token global batch takes 2.00 seconds per step at 40% MFU, completing a 1-trillion-token run in 5.5 days (33,800 GPU-hours).
